## Review A — Overall take 1

Raven is far more serious than a student side project usually is: a dependency-free curses workbench of ~109K LOC across 269 modules, 17,145 tests (I collected them; the full run is ~10 min), a real differential painter, a Light/Heavy split where analysis runs inside an owned `salloc`/`srun` step with placement verification, length-prefixed canonical-JSON protocols with hard budgets, an AST-whitelisted expression language, atomic checksummed `ui.json`, and evidence receipts that refuse to claim completeness when gaps exist. The strategy doc and ledger are unusually candid about "delivered" vs "external gate". That is substantial.

What worries me is the shape of the project rather than any one module:

- **Breadth has outrun validation.** All 40 investments, the 10 advanced proposals and the tracer are marked delivered, yet nearly every ledger row ends in "External gate": no real `squeue` has ever run in CI, no production SSH, no GPU, no multi-node. `FakeBackend` is realistic about text formats, not scheduling. 18 execution drivers are still deferred — the analysis kernels are real, the handoffs aren't.
- **The core is a timed poll.** The loop sleeps on `getch` with a 1–200 ms timeout and nothing can wake it (no self-pipe/eventfd); sampler, PTY broker and worker sockets are polled per tick. That's why your own idle benchmark reads ~5–6% mean / p99 63% of a core against the 1% goal — the one goal the validation record admits is unmet, and it's structural.
- **Slurm is reached by delimiter-parsing CLI text.** `squeue -o '%i|%j|…'` with 23 fields and a sentinel; `parse_kv` splits `scontrol -o` on whitespace, so `Command=`, `WorkDir=` and `Reason=` values with spaces are corrupted (and the allocation helper's lease math reads `TimeLimit` through it); short rows are dropped silently; no `--json`, no slurmrestd. `ravenh` also builds its SSH backend with `control=False`, so every poll pays a full handshake.
- **A few real bugs under the rigor:** series archives are keyed by job id only (`state/series/<jobid>.jsonl`), so a requeued attempt's samples merge into the previous attempt's file; `tags.json` is written non-atomically with errors swallowed; the plugin dir loads every `*.py` with no owner/mode check while the config (which can hold `shell=True` hooks) has no permission check either; there is no single-instance lock on the state dir.
- **Duplication and drift:** three copies of the same framing codec (`raven_protocol`, `raven_allocation`, `terminal_service`) with different limits; hand validators in every module while the 65 JSON Schemas are documentation only; exact-key-set validation that breaks on any additive field; a flat package with zero sub-packages. The `codex/*` branches, zero git tags at version 7.0.0 and a single squashed commit point to a mostly agent-driven process — fine in itself, but it's the pattern that produces feature museums. The next phase should be proof and subtraction, not more surfaces.

Twenty directions follow. **(P)** = practical, landable in days–weeks; **(B)** = bold.

### Prove it on real Slurm

1. **Real Slurm in CI (P).** Run a slurmctld+slurmd container (slurm-docker-cluster style) in GitHub Actions nightly across 23.02/23.11/24.05/24.11, and execute the existing FakeBackend-shaped tests against real `sbatch`/`squeue`/`sacct`/`scontrol`. One job converts ~30 "External gate" rows into evidence and will surface the `parse_kv` and short-row problems on day one.
2. **Version-gated `--json` reads plus a recorded output corpus (P).** Prefer `squeue --json` / `sacct --json` / `scontrol show job --json` (data_parser-versioned) with the pipe format as fallback; keep a corpus of captured outputs per Slurm version and fuzz the legacy parsers against it. Surface a parse-error counter instead of empty tables, and drop the `sacct -S 1970-01-01` scan.
3. **Property-based and fault-injection suite (P).** 17K tests, zero Hypothesis. Target the byte-level input decoder, all three `Decoder`s (fragmentation, garbage, major-version skew — currently untested), `expr`, evidence canonical/digest round trips and `series_archive` merges. Add a chaos harness: kill the worker mid-frame, SIGSTOP `srun`, drop the ControlMaster socket, truncate a JSONL mid-line, and assert the reconciliation outcome. Add pytest-xdist to get the suite under three minutes.

### Fix the core loop and storage

4. **Event-driven UI loop (P, biggest single payoff).** Replace the timed `getch` with `selectors` over stdin plus a self-pipe written by the sampler, PTY broker and allocation socket; wrap `doupdate` in DEC 2026 synchronized output to kill tearing. Idle should drop from ~5% to well under 1% with lower input latency, and the `wait_ms()` clamps go away.
5. **Attempt-scoped, binary, tiered series store (B/P).** Key archives by (job, attempt) to fix the contamination bug, then replace JSONL with an append-only, block-checksummed, mmap-able format (delta-of-delta timestamps, XOR floats; stdlib `array` + zlib is enough) with a min/max pyramid so rasterization is O(width) rather than O(points). Replace "stop writing at quota" with raw → 10 s → 1 min rollups. The double-pickle signature fallback in `native_series_cache` disappears once real revisions exist.
6. **One codec, one validator, loaded schemas (P).** Merge the three framing codecs; make the 65 schemas the runtime validators (tolerating unknown fields, carrying migrations) instead of exact-key-set checks that break on additive fields. Stop serializing receipts three to four times.
7. **Package structure and gates (P).** Split `raven/` into `ui/`, `model/`, `scheduler/`, `heavy/`, `evidence/`, `ops/`, `terminal/` with import-linter layering contracts, ruff and a formatter (329 lines exceed 200 chars), and a mypy-strict ramp with `py.typed` (12% of functions have return annotations). Dissolve `controller.App` (`_handle` ≈400 lines, `run_command` ≈270-line if/elif) into the command registry that already exists.
8. **Single-instance, atomic, NFS-honest state (P).** flock the state dir, write `tags.json` atomically, apply the `st_uid`/`mode & 0o077` checks from `runtime_control.py` to config and plugin dirs, and define an explicit policy for state on network filesystems (you already refuse them for the SQLite cache).

### Architecture bets

9. **`ravend`: a per-user session daemon with thin clients (B).** Move Store/Sampler/collection into a long-lived login-node process on a Unix socket speaking the protocol you already have; the curses TUI, `raven --json/--watch`, a VS Code or Open OnDemand panel, and Jupyter become clients. SSH drops stop killing sessions (tmux-style reattach), and the remote reader stops shipping 120 KB of module source in argv on every call.
10. **Admin-installable shared host collector with SO_PEERCRED (B).** The 200 users × 1 query/min ≈ 3.3 qps concern is real. One governed `squeue`/`sacct` fan-out per login node, filtered per authenticated uid, is what administrators want — and the adoption wedge that gets Raven approved on a cluster. `shared_collection.py` is already the per-user version.
11. **Fail-open worker recovery (P).** Today any pipe or SSH loss parks the allocation in `cleanup_uncertain` and blocks future starts until a human looks. You already scrape the job id; add an automatic `squeue`/`scancel` reconciler with bounded retries, and replace the 10–100 Hz sleep-polls in the helper, router and client with select-driven waits.
12. **WASI adapter sandbox (B).** The ledger admits "isolation is not a security sandbox". Compile adapters to WASI and run them under wasmtime (optional extra) with capability-scoped FS/network and fuel metering: deterministic, bounded, and the first real sandbox in this space. Plugins stay trusted; adapters become safe to run untrusted.
13. **SQLite as the evidence query engine (P, stdlib).** Ingest attempts, transitions, metrics and log-line indexes into a per-project `evidence.sqlite`, expose `raven query "SELECT …"` with lnav-style views, make `expr` sugar over it, and add the missing time-series primitives (`rate`, windows, deltas) with an evaluation budget. Exports become one compact SQLite bundle instead of long-form CSV repeating 18 identity columns per row.
14. **Perfetto self-trace (P).** Emit Chrome trace-event JSON from the `_timed_ui` spans (document/paint/flush/input_wait/sampler/worker) so a p99 stall becomes a flame graph in ui.perfetto.dev rather than a number in a benchmark file. The same move fixes the Python tracer: block-level hashing, `sys.monitoring.DISABLE` for ignored code objects, and Perfetto/speedscope output instead of a per-event SHA-256 that costs 10–100×.

### Product and research directions

15. **Backfill-aware, counterfactual queue forecasts (B).** You have split-conformal intervals keyed on cohorts. The novel step is modeling the backfill window from `pending_ahead`, reservations and node idle gaps you already collect, and answering "if I ask for 4 h instead of 12 h, what's P(start < 10 min)?" — request-shaping advice validated against recorded outcomes. No user-side tool does this.
16. **Rank-divergence log analysis (B).** For MPI jobs with per-rank logs, template-mine lines (Drain-style) and find the first point where a rank's template stream diverges from the majority; show the lonely rank, its last common line and the diff. `log_match_index` and the log workbench are the foundation; lnav doesn't do cross-file divergence.
17. **Online anomaly detection on live metrics (P).** There is no CUSUM/EWMA/MAD anywhere and live streams are never analyzed. A few hundred lines gives "RSS trend hits the limit at 14:52", "GPU utilization collapsed at step 3000", "I/O stall across ranks" — with the same abstention discipline the advisor already uses.
18. **SSH-key-signed evidence bundles (B/P).** Every digest is unkeyed: integrity without authenticity. `ssh-keygen -Y sign/verify` exists on every cluster; sign the canonical receipt digest with the user's key, ship an `allowed_signers` file in the RO-Crate export, and a reviewer verifies a result without installing Raven. Zero new dependencies.
19. **`raven mcp`: a bounded read-only tool server for AI investigators (B).** Expose attempts, receipts, bounded logs, `expr`/SQL queries and the investigation timeline over MCP so Claude Code or any agent can investigate a failed job with no shell or scheduler access — exactly the "structured, evidence-linked queries through the same bounded APIs" your strategy insists on. Mutations stay behind the existing review-and-receipt flow.
20. **Subtract, then study (P).** Ship `raven-core` (monitor, launch, logs, run home — a few dozen modules) as the thing admins audit, with science/ops operations as an optional `raven-lab` extra; tag and Sigstore-sign releases in CI. Then run the five-journey G5 study with five labmates on CARC, demo backend first, real account second. Features are no longer the bottleneck; users and real-cluster evidence are.

Honourable mention: kitty/Sixel raster plots with braille fallback — nobody in the Slurm TUI space does it.

## Review B — Overall take 2

Ten more, all buildable against the demo backend, a local Slurm container, your own account's `sacct`/`sprio`/`sshare` output, or processes inside your own allocation — nothing waits on an admin, a site, or someone else's data.

1. **A Slurm digital twin (research, 2–3 months).** `FakeBackend` has no scheduling semantics and `execution_simulator` is DAG replay. Build a discrete-event model of the multifactor priority plugin, backfill (`bf_window`, `bf_max_job_test`), fairshare decay, reservations and QOS group limits, parameterized from `scontrol show config` and `sacctmgr show qos`, and calibrated by replaying your own recorded `sprio`/`squeue --start`/`sshare` traces. Payoffs stack: scheduler-aware CI without Docker, a validation harness for the queue forecasts, and "if I submit now vs. at 8 pm" answers. The Slurm simulator literature exists; a user-space twin that self-calibrates from one account's traces does not.
2. **Fairshare-aware submission shaper (research/product, 1–2 months, builds on #1).** A user-side meta-scheduler that orders, staggers and times a campaign's submissions under `MaxSubmitJobs`/`GrpTRES` limits to maximize throughput of the whole campaign rather than one job — e.g. release the long array after the fairshare factor recovers, or interleave short backfill-friendly tasks ahead of the big allocation. Measure against naive submit-everything in the twin, then in your own account. Nobody does submit-time optimization for the researcher.
3. **Time-travel scrubber (product, 3–4 weeks).** You already retain `job_transitions`, `events.jsonl` and per-job series archives. Reconstruct the Jobs/History/Analytics views at any past instant, scrub with `[`/`]`, and diff two instants ("what changed between 13:40 and 13:52?"). This is the UI for every "why was it pending?" conversation, and the replay fixtures double as deterministic regression inputs.
4. **Unprepared-program state profiler (product, 3–4 weeks).** For binaries you cannot rebuild, the Heavy step on the node can read `/proc/<pid>/{stat,schedstat,io,wchan,status}` for every rank and thread of your own job: running vs. runnable-but-waiting vs. D-state vs. voluntary sleep, context-switch rates, read/write bytes, CPU migrations. Sample at 100 ms, attribute wall time per rank, and flag "rank 37 spent 40% in D-state on `/scratch`". No ptrace, no root, no instrumentation — it fills the gap your tracing contract explicitly leaves open.
5. **Unsupervised phase segmentation and cross-run alignment (research, 1–2 months).** Segment CPU/GPU/IO telemetry into phases with change-point detection (PELT or binary segmentation on the retained series), then align phases across attempts with DTW so two runs compare phase-by-phase without any application hooks. Evaluate recovery of known phases on the demo producer and the automated-reporting example, then on real jobs. It gives "Compare" a time axis that means something.
6. **Allocation health fingerprint (product/research, 4–6 weeks).** Spend the first ten seconds of every Heavy step and, optionally, every launched job on a calibrated micro-benchmark: memory bandwidth per socket, local scratch write/read, intra-allocation MPI ping-pong, GPU memcpy if present. Store it as an evidence receipt bound to the attempt. Later comparisons discount variance from a sick or noisy node, and a bad fingerprint can stop a 12-hour run before it starts. It runs on node-time you already own.
7. **Young–Daly checkpoint advisor (product, 2–3 weeks).** Estimate node MTBF from your own `sacct` history (`NODE_FAIL`, `TIMEOUT`, preemptions) per partition, measure checkpoint cost from the declared checkpoint files S01 already understands, and compute the optimal interval τ ≈ √(2·C·MTBF) with its sensitivity. Surface it in the launch wizard and the recovery review. Small code, large expected node-hour savings, and it composes with the existing checkpoint contracts.
8. **Model-checked ownership and protocol state machines (research/engineering, 4–6 weeks).** The allocation receipt (grant/cancel race, reuse, `cleanup_uncertain`), the pointer lease, and the worker accepted→running→committed→ack flow are small state machines. Specify them in TLA+ (or as Hypothesis stateful tests driving the real classes) and let the checker find the paths where a lost ack or a stale receipt leaves work blocked. Generated counterexample traces become regression fixtures; this is how to make "fail-open recovery" safe rather than hopeful.
9. **Query-preserving trace sketches (research, 2–3 months).** Your R5 is marked exploratory because the query family is undefined. Define it: per-phase, per-rank count/sum/min/max, a t-digest for latency quantiles, and top-k by duration, each with a stated error contract — all implementable in stdlib. Emit the sketch alongside or instead of the raw journal, and have the UI answer "is this question answerable from the sketch?" before it asks for raw evidence. Validate against full journals from the PMPI wrapper and Python recorder you already ship.
10. **Nondeterminism attribution campaigns (research, 1–2 months).** When two attempts disagree in the last digits, design the experiment automatically: repeat runs toggling `OMP_NUM_THREADS`, MPI reduction order, deterministic-GPU flags and rank count in a small factorial, measure output variance per factor, and report an ANOVA-style decomposition ("90% of the drift is reduction order"). The `regression-sweep` and `numerical-stability` scaffolding supplies the runners and tolerances; the new part is the design and attribution. Demonstrable end-to-end on a tiny MPI reduction example in the repo.
