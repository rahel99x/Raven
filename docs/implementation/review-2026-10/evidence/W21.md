# W21 — Signed evidence bundles

## Source and baseline

Source A-18; baseline `33316a08bd583a242356c7722a21c10e00cff21b`.
The existing `research-portable` operation already imports/exports evidence and
RO-Crate documents through a reviewed, no-clobber publication path. It lacked
signatures and independent trust verification. Reusing that path avoids another
export format, permission model or publication implementation. [Current source hashes](raw/W21-source-hashes.json) identify the measured implementation; the final integrated revision remains a tranche gate.

## User path and design

The operation palette's `:ops research-portable` form adds optional signing key
and principal fields. Inspect detects OpenSSH signing support and displays the
public fingerprint without signing. Review/Confirm Apply rechecks the reviewed
source and key, signs exact generated bytes, then uses the existing publication
function. The equivalent palette `:ops run research-portable ...` uses the same
path. There is no shell `raven ops` command; documentation does not claim one.

A private key stays local and must be owned/private. An agent-held key can be
selected through its readable public file; Raven never asks for a passphrase or
automatically loads an agent. Key descriptor and mutation identity remain pinned
across derivation and signing. Changed/replaced keys invalidate the action.
Explicit signing errors never downgrade to unsigned export. Unsigned export has
no OpenSSH dependency. Cancellation is checked before signing and publication;
each trusted local OpenSSH invocation has a ten-second deadline.

The simpler alternative, signing only the existing receipt, would not bind every
exported artifact and could falsely suggest those files were authenticated.
Signing one canonical manifest plus detached signature retains portable formats
while making the signed byte scope explicit. No private key or local private-key
path is copied into output. Publication preserves incomplete markers, receipt-last
completion and refusal to overwrite an existing directory.

## Manifest contract

`raven.signed-evidence-manifest/v1` and namespace `raven.evidence.v1` bind the exact
attempt identity, schema, publication receipt, each artifact's byte length and
SHA256 digest, and descriptive signer public key/fingerprint. Canonical JSON bytes
include one final newline. Authenticity means possession of an independently
trusted key. Scientific validity and trusted timestamp claims are explicitly
false; neither a local signature nor a user-supplied attempt establishes scheduler
ground truth. A JSON Schema documents the structural contract.

## Verification

`raven/evidence_verify.py` is a standalone standard-library file plus OpenSSH,
tested from a trusted copied path using `python -I -S` without importing Raven.
It requires an independently chosen principal and allowed-signers file outside
the bundle. Bundled key metadata is descriptive and never automatically trusted.
Pinned descriptor-relative traversal rejects writable or symlinked trust
ancestors; final trust-file replacement during verification is detected.

Verification authenticates exact manifest bytes first, checks namespace and
canonical representation, compares the signature's actual public key with
descriptive metadata, then hashes all declared artifacts and checks receipt and
identity. Incomplete publications, symlinked artifacts and traversal are rejected.
Unsigned extras are reported separately. Bounds: manifest 256 KiB; up to 64
artifacts, each 16 MiB, 64 MiB total; directory inspection 128 entries; JSON depth
64 and 200,000 values. OpenSSH capture is checked after process exit: it is not a
streaming memory cap. The local executable is trusted, its key/input sizes are
bounded, and execution has a deadline. Linux `/proc/self/fd` is required for this
optional signing/verification path.

## Review conclusions and measurement

Independent maintainer review found two substantive issues: unsafe ordinary
pathname traversal to the independently trusted allowlist, and unbounded JSON
depth during subsequent canonicalization. Both are corrected with regression
tests. The private key never enters export serialization; reviewed scope,
cancellation, atomic publication and unsigned compatibility remain intact.

Final integration exposed an unsigned-filesystem identity edge case: overlay
inodes and device IDs may exceed the worker protocol's signed integer range.
Signing review now encodes these opaque atoms as exact bounded decimal text;
negative/invalid identities fail. The signed artifact format and strict worker
integer validation are unchanged. Old ephemeral previews safely require a new
review after updating. Worker-wire round-trip regressions cover values through
`2**64-1`; all real signing, verifier and UI checks remain intact. The focused
signing/shared/session/WASI run passed **146 tests in 6.06 seconds** after this
correction. The measurements below precede this small review-identity encoding
change. Their raw records survived the environment reset; the temporary harness
did not. The persistent replacement `scripts/benchmark_signed_evidence.py` now
compares current unsigned exports, actual signed exports, and a deliberately
narrow old-identity-helper comparator using one shared 1,000-metric fixture and
generated test key. It asserts identical data artifact hashes and signed bundle
sizes and verifies every signature. Its one-repeat functional smoke passed;
the final controlled run is recorded below. This is not a reconstructed historical
build.

[Controlled measurements](raw/W21-export-cost.json) used the same 1,000-metric
fixture in two interleaved baseline/candidate/signed cycles, ten exports per fresh
process. Mean unsigned export: baseline 148.33 / 153.60 ms, candidate 148.80 /
149.46 ms. Optional signed export: 181.18 / 177.82 ms, an added 28–32 ms over its
matching candidate; standalone verification averages 9.39 / 9.11 ms. Unsigned
output stays 81,543 bytes; signing adds 1,431 bytes. No speedup is claimed.

Process CPU per ten exports: baseline 1.484 / 1.537 s, candidate unsigned 1.487 /
1.494 s; signed including verification 1.613 / 1.594 s plus joined OpenSSH child
CPU 0.301 / 0.284 s. Peak process RSS: baseline 17,920 KiB; unsigned candidate
18,236–18,240 KiB; signed 18,792–18,868 KiB. These are OS process RSS measurements,
not Python allocations or process-tree peaks. A preliminary overlapped run was
discarded; only serialized quiet-window results appear here. These
are local cryptographic and UI qualification results, not a live cluster, remote
key service, scientific-validity or trusted-timestamp attestation.

The [persistent final harness](raw/W21-signing-cost-final.json) ran five exports
per fresh process during the exclusive 01:24:21–01:24:24 UTC window. Current
unsigned exports averaged 152.26 ms; signed exports averaged 187.25 ms, adding
35.0 ms. Verification averaged 9.54 ms. The narrow old-identity-helper comparator
averaged 190.63 ms signed and 8.91 ms for verification. This small sequential
sample does not establish a meaningful identity-helper speed difference. It
does establish preserved artifact hashes and identical 81,103-byte signed
bundles across both helpers; the shared unsigned fixture was 79,610 bytes.

Across five exports, unsigned parent CPU was 0.76233 seconds. Corrected signing
used 0.83229 parent seconds, including verification and fidelity checks, plus
0.15580 joined-child seconds. The old-helper comparator used 0.85004 parent and
0.15026 child seconds. Parent maximum RSS was 23,872/24,004/24,020 KiB for
unsigned/corrected/old-helper cases; each signed child's maximum RSS was the
same as its parent high-water value. These are process maxima, not Python
allocations or simultaneous tree peaks. Fixture construction, imports and key
generation are excluded from export latency; process RSS includes imports.
The generated fixture differs from the earlier transient harness, so these two
reports must not be treated as an equivalent historical before/after comparison.
The [final window receipt](raw/W39-W21-final-controlled-window.json) records exact
commands and successful child joins; source hashes are embedded in the raw report.

Installation uses the normal Raven update. Signing requires OpenSSH with `-Y`
support; verification can instead use the trusted standalone file. The
[guide](../../../guides/signed-evidence.md) gives independent allowlist and direct
OpenSSH recipes. Rollback is simply leaving the optional signing fields empty;
existing unsigned bundles and formats remain compatible.
