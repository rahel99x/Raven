# W43 — Optional terminal raster prototype

Source: A-H1. Baseline revision `33316a08bd583a242356c7722a21c10e00cff21b`.
Existing Braille/ASCII chart rasters, published geometry, pointer ownership,
partial painter and W19 synchronized flush are reused. No optional terminal image
transport existed in the baseline.

## Design and complete path

`terminal_raster = "kitty"` in the ordinary UI config explicitly enables a
conservative prototype when interactive Kitty environment capability is present.
Default is off. Unknown terminals, noninteractive output, SSH and multiplexers
fall back. Sixel is separately documented and falls back; it is not treated as
an equivalent framing or lifecycle protocol.

One fully visible plot's existing Braille occupancy becomes bounded RGBA. No
new samples, interpolation or scientific resolution are invented. Axes, labels,
source rows, copy/export and mouse coordinates remain authoritative. Only the
painter's graph-cell copy is masked while its image is displayed. Before flushing
an overlapping overlay, selection, captured pointer, resize, view change, clipped
plot or terminal handoff, Raven deletes its own image and restores ordinary text.
Write failure forces the current text canvas to repaint. Exit cleanup is
idempotent. Kitty q=2 emits no graphics responses into the input path.

The simpler alternative is retaining existing Braille everywhere; that remains
the default and complete fallback. A general Kitty/Sixel abstraction would hide
real protocol differences and demand premature terminal support. The prototype
uses Kitty-specific IDs/chunks/deletion, at most 80×24 cells (160×96 RGBA pixels),
128 KiB encoded output and two image updates per second. Changed source data
falls back to fresh text when the rate cap prevents a new image; stale pixels
never sit under new axes. The explicit prototype uses monochrome pink occupancy,
not higher resolution or original per-cell semantic colors. A plot containing
multiple occupied-cell styles falls back to its complete colored text so
threshold/category differences cannot collapse into one color.

## Validation and independent review

The renderer suite checks exact occupancy, bounds, unsupported protocols,
overlay/selection/capture/resize/view lifecycle, original rows, pointer geometry,
exclusive own-ID deletion, rate limits, failure recovery and config schema.
Actual curses-hook tests assert delete → flush → image ordering and immediate
text reflush after an image-write failure. Existing synchronized output, quiet
frame/input and real outer-PTY tests retain their behavioral assertions.
Combined selection: **94 passed**; latest W27/W29/W43 focus: **49 passed**.

Root independently reviewed renderer/screen ownership, fallback repaint,
view/overlay lifecycle and partial updates; no substantive integration finding.
The monochrome styling limitation remains explicit and does not change exports.
Post-measurement review added the multistyle fallback with removal/repaint
regressions. It leaves the measured encoder and default-off UI path unchanged.
The final combined selection passed **203 tests in 5.38 s**, with quality gates
passing. Actual emulator/tmux/SSH visual qualification remains separate below.

## Performance and deployment gates

`scripts/benchmark_terminal_raster.py` measures encoding CPU, Python allocation
peak, separate process RSS, exact transport bytes and local raw PTY write/drain
cost. The acknowledged controlled run on 2026-10-18 measured 2.816 ms median
encoding across 50 maximum-size images. Local raw PTY write/drain averaged
0.184 ms per image across 20 images. Each image used 82,232 transport bytes;
the two-Hz cap permits at most 164,464 bytes/s for this fixture. Python peak
allocations were 391,481 bytes and whole-process maximum RSS was 14,956 KiB.
Raw results: `W43-measurements.json`; coordinated times/hashes:
`W27-W29-W36-W43-benchmark-window.json`. Raw PTY transport is not emulator
rendering, network or visible display latency.

Actual Kitty rendering, Sixel investigation beyond protocol design, tmux/Screen
passthrough, SSH forwarding and human visual/accessibility qualification require
those terminals/transports. Fake protocol/curses tests cannot establish those
results. Default enablement remains blocked on that external UX evidence; no
novelty or increased scientific fidelity is claimed.
