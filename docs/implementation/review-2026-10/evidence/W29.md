## Ownership and complete path

The Operations **Observe an owned local process** tool reviews an explicit PID,
start ticks, UID, node, duration, requested interval and new destination. Light
defers; the authenticated Heavy worker supplies collector placement independently
of caller context. Apply requires the same reviewed worker and target identity.
The worker task is cancellable and never signals, ptraces or changes a workload.

The target is explicitly local and same-UID. Requiring its Slurm cgroup to equal
Raven Heavy's allocation would incorrectly exclude another owned scientific job
on the same node. Therefore the collector's verified allocation is retained
separately and target scientific-job/rank attribution is **unknown**. No UI job
selection or Heavy allocation is borrowed as proof. Another node needs its own
verified collector; one receipt never asserts whole-allocation coverage.

Pinned `/proc` descriptors, PID/start time, UID and every ancestor parent edge
are checked before committing task counters. Exited/zombie roots stop sampling.
The kernel's optional task children files are reused; when absent, a bounded
1024-PID same-user ancestry metadata scan discovers candidates. Only verified
members' counters are retained. Limits: 32 processes, 128 retained task identities,
600 samples, 0.1–60 seconds. Requested 100 ms sampling adapts to measured collector
cost up to two seconds; saturation stops explicitly. CPU target is a feedback
target, not a universal hard overhead guarantee.

Available per-task states, CPU ticks, scheduler runtime/run-delay, context
switches, I/O and migrations are recorded with explicit unavailable fields.
Disabled scheduler statistics are unknown. R is running-or-runnable; D identifies
neither a filesystem nor cause. Proportions are point-observation proportions,
not exact dwell time. Deltas span first/last valid observations, with resets and
missing boundaries left unknown. Receipt files are immutable/private; no automatic
retry reuses a stale PID review.

## Alternatives, validation and review

A simpler PID-only polling loop is smaller but unsafe under reuse/reparenting.
A ptrace/perf collector would add permissions, workload interaction and event
semantics outside the accepted sample-based scope. Bounded read-only descriptors
and independent Heavy enforcement are the smallest complete supported path.

Initial focused **13 tests passed**, including an actual managed WorkerClient
review/capture/private receipt, PID reuse and exit, task churn, cancellation/fd
cleanup, missing counters, owned descendants and unrelated-process exclusion.
Independent review by the state/ownership agent found a real gap: checking each
ancestor's identity without checking every parent edge accepted a reparented
intermediate ancestor. The full edge check and zombie rejection fix it. Dedicated
negative-chain and foreign-UID regressions are included; the combined post-recovery
selection passed **102 tests**. A further own-process UID recheck retains the
same behavior and passed the focused **49-test** W27/W29/W43 selection. The
final combined selection passed **203 tests in 5.38 s**; quality gates passed.

No scientific process is signalled by these tests. Fixture processes created by
the test harness are explicitly owned and cleaned up separately by that harness.

## Performance and qualification

`scripts/benchmark_process_profile.py` runs three interleaved repetitions of the
same local CPU workload with collector off/on, checks identical answers, and
reports workload seconds/slowdown, collector CPU, actual intervals, task coverage
and process RSS. The acknowledged controlled run on 2026-10-18 measured median
workload duration 1.040 s off and 1.014 s on (−2.51% observed, treated as noise,
not a collector speedup). All six answers matched. The three collector runs used
6.07–7.80 ms CPU, retained 10–11 observations of one task, and requested 100 ms
intervals (one adaptive interval 110.37 ms). Whole-process maximum RSS was
13,824 KiB. This kernel lacked task children files; each sample explicitly
reported the bounded ancestry fallback and root-exit termination. Raw results:
`W29-measurements.json`; coordinated times/hashes:
`W27-W29-W36-W43-benchmark-window.json`.
No live multi-node, GPU, hidepid deployment or universal overhead qualification
is claimed. Kernel permission failures are tested with explicit fixtures.
