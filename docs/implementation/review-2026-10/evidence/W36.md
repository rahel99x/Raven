# W36 — Query contracts for trace summaries

Source: B-09. Baseline revision `33316a08bd583a242356c7722a21c10e00cff21b`.
The existing checked journal/reader and W20 matched-interval export are reused.
The baseline had no persisted query-preserving phase/rank summary contract.

## Design and complete path

`raven trace summary create|query|merge|delete` provides bounded, private,
no-clobber persistence and explicit errors. The Trace panel's Summaries/Events
control uses its existing background subscription and exact-attempt lifecycle;
painting performs no journal reads. Original trace inspection remains available.

Counts, sums, extrema and top-32 durations are exact **within matched retained
intervals**. Unmatched boundaries and missing ranks remain unknown. Recorded
phase/name/function fields provide labels; an opening event's rank is declared
by the emitter, not inferred from a filename or process position. Wall durations
may overlap and do not become CPU accounting by summation.

A simpler sorted exact list provides all quantiles but grows with every retained
interval. A deterministic seven-significant-bit integer histogram instead gives
an explicit interval containing the nearest-rank duration. Small durations below
128 ns are exact; larger bin width is less than 1/64 of the represented positive
value. This is a **value interval**, not a universal rank-error guarantee or a
claim about t-digest. Count/sum/extrema/top-k remain separate exact aggregates.

Every query reports exact/approximate/unanswerable before its value. Identical
bins merge without weakening their bound; overlapping ranges of the same exact
stream are refused. A summary retains at most 16 source contributions, 64 total
groups, 8192 bins and 4 MiB. Whole-source deletion is supported. A time window
must include complete source contributions in one node/boot monotonic clock
domain; boundary-cut/cross-node windows abstain. Order and causality always
remain unanswerable from this summary.

Version, parameters, units, source digests, stream identities, retained sequence
and time bounds, coverage, unmatched events and warnings persist in the file.
A digest references evidence; importing a summary is not source authentication.
Raw-journal retention is explicitly independent. Creating, merging or deleting
summary contributions never deletes a journal. New destination names protect
recovery after an interrupted publication.

## Validation and skeptical review

Focused recorder/export/summary/UI selection: **40 passed**. Tests exercise
constant, heavy-tailed and adversarial durations, every percentile from 0–100,
merge bounds, duplicate-stream rejection, deletion, time-window abstention,
unknown boundaries, malformed inputs, and actual CLI private persistence.
Synthetic test intervals are written into full checked journals rather than
being claimed as observed scientific workloads. The final combined selection
passed **203 tests in 5.38 s**. Subsequent skeptical import review made query
scope canonical, validated retained coverage/status/warnings/loss metadata, and
checked extrema/top-k consistency against histogram frequencies. Descriptive
extensions remain allowed; an imported descriptive claim cannot widen the query
contract. Malformed-file and missing-scope regressions passed.

Review added structural and aggregate consistency validation (including sum
bounds, histogram counts and exact top-k maximum), refused silent bin/group
truncation, and kept partial-window queries explicitly unanswerable. Deployment
remains experimental; no summary replaces an authoritative retained journal by
default.

## Performance and qualification

`scripts/benchmark_trace_summary.py` measures complete synthetic analysis
fixtures: ingestion milliseconds, separate Python peak allocations/process RSS,
encoded size, query latency and exact observed quantile errors against full
interval lists. The acknowledged controlled run on 2026-10-18 measured 4,000
interval ingestion at 6.528 / 8.783 / 7.046 ms for constant / heavy-tailed /
adversarial fixtures. The initial five-query-plus-exact-oracle checks cost 0.413 / 18.452 / 3.101 ms;
those numbers include sorting/assertion overhead and are not pure query latency.
The corrected harness excludes the oracle from timing; its post-validation
controlled refresh is recorded below.
Every exact requested quantile lay within its reported bin; midpoint errors
remain in `W36-measurements.json`, including large absolute errors for synthetic
multi-day durations. Encoded summaries were 3,023 / 90,702 / 9,092 bytes versus
1,138,809 / 1,206,064 / 1,195,340 bytes of synthetic event JSON. Python allocation
peaks were 516,900 / 1,284,720 / 547,280 bytes; whole-process maximum RSS was
24,856 KiB. These distributions demonstrate the explicit bounds, not a universal
compression ratio. Coordinated times and hashes are in
`W27-W29-W36-W43-benchmark-window.json`. No live MPI, GPU, scheduler or universal
scientific compression result is claimed.
