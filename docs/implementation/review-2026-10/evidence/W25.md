# W25 — Explicit retention tiers and source protection

Source A-05; baseline `33316a08bd583a242356c7722a21c10e00cff21b`. Depends on W06 durable identity and W24 bounded exact blocks. The baseline retained raw JSONL and memory tails, with no typed tier archive or query semantics.

The delivered optional `.rvt` working archive contains one versioned manifest and disjoint raw/recent, 10-second and 60-second tiers. Ages, gap threshold and raw protection are configurable through managed `storage.retention` settings and explicit CLI arguments. Setup previews and publishes the configured policy, then displays tagged tier results in the same storage page. `raven series retention`, `inspect`, `query` and `pin` provide the reproducible command path. Queries label raw/rollup fidelity; rollups never feed native raw charts or raw exports.

Each aggregate carries counts, time bounds, first/last observed times, exact decimal sums, min/max with physical source-row provenance, observed/missing metric counts and explicit units. Native CPU ratios remain fractions, RSS bytes, GPU utilization percent and GPU memory MiB; unknown units remain null. Sums use sufficient decimal precision to retain the original finite binary64/integer arithmetic without overflow. There is no interpolation or time-weighted-integral claim. Gap provenance is retained explicitly. Boundary queries return full intersecting bins marked partial rather than inventing precise clipped results. Tier windows do not overlap, and retained raw rows have unique physical source positions.

Raw protection is enabled by default. A pinned working archive must be explicitly unpinned before shortening raw retention. Pin metadata is distinct from the aggregation policy; pinning existing rollups never relabels them as raw. The source path, attempt identity and canonical raw-value digest remain in the archive. Raw samples and project scientific files are never erased by this workflow. Retention expiration applies only to the working copy.

**Conservative scope adjustment:** original raw garbage collection is deliberately absent. Raven cannot establish whether every external scientific receipt or exported result still references an original file. Inferring deletion authority from locally absent references would violate the accepted protection requirement. Smaller working archives are useful for bounded queries, but total disk use includes preserved raw originals. Benchmarks report these quantities separately. A future original-file deletion path requires a reference-aware policy and explicit protected-source registration; no such deletion is implied by the current controls.

The simpler alternative is to retain raw data only. It preserves fidelity but gives no explicit bounded summary tier. A multi-file generation database is unnecessary at the admitted working size: a single staged checksummed block file contains the complete policy, provenance and tier records. Atomic replacement publishes one complete generation. Cancellation, CPU/wall/address-space limits, disk-full, quota or source changes leave the previous generation and original raw source intact. Setup uses W24's owned local child; apply requires the state writer lock. Late corrections rebuild from raw source, avoiding guessed aggregate subtraction. Corrupt generations are rejected explicitly and never served as silent partial tier coverage.

Runtime budgets are 50,000 input records and 32 MiB encoded input/output, plus W24's cumulative decoded-byte bound and explicit gap/provenance limits. Unknown schema, invalid counts/time bounds, overlapping intervals, malformed aggregates and duplicate flattened GPU metric names are rejected. The independent review identified the duplicate-metric collision and incomplete manifest validation; both are covered by negative regressions. Synthetic tests exercise extreme floats/integers, irregular samples, unknown units, missing fields, correction rebuilds, protected evidence, boundary queries, cancellation, disk/quota failure, corruption and real CLI/state ownership.
