## Design and complete path

The model uses the first-order Young loss model with finite useful-work length and integer equal segmentation. It reports write cost, expected lost work and restart cost separately; the final successful segment does not incur a useless checkpoint. Exact small-count Poisson exposure intervals, descriptive duration ranges and endpoint sensitivity bound the assumptions. Explicit estimated MTBF/cost ranges remain labelled estimates. Node failures inform interruption hazard; timeout and preemption records contribute censored exposure, while notice and remaining wall time are separate feasibility checks. Zero failures, missing exposure, biased/nonstationary samples, incompatible restart support and frequent interruptions cause explicit abstention. File size and modification time never become measured write duration.

A simpler fixed interval would avoid estimation but cannot explain application costs or sparse failures. A more elaborate renewal model would introduce unsupported failure-during-restart assumptions. The selected approximation exposes its validity domain rather than presenting an exact optimum. It compares advised/fixed/no-checkpoint policies with uncertainty; the advice does not signal, modify, submit or requeue jobs.

`checkpoint-advice FILE` and Research share one receipt. Setup supplies exact implementation guidance. Optional advanced launch settings/`--checkpoint-advice` use a stable bounded project-relative read; the receipt participates in the reviewed-plan fingerprint, so changed evidence requires another review. The existing checkpoint recovery recipe can embed the same input and presents identical assumptions. Original checkpoint hash, application/runtime compatibility and source-attempt verification remain required.
