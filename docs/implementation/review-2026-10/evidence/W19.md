# W19 — Synchronized terminal output

Source: A-04. Baseline revision: `33316a08bd583a242356c7722a21c10e00cff21b`.
Candidate implementation is in the current integration tree; controlled cost and
local tmux checks are recorded below. Final integrated revision gates are pending.

## Implementation and alternative

The existing renderer had no DEC 2026 negotiation or balanced frame boundaries.
`terminal_sync.py` owns one bounded capability query, its decision and frame
counters. The UI input decoder consumes exact replies to that query. The renderer
brackets only the complete changed-frame `noutrefresh`/`doupdate` flush in a
`finally` region; composition, input waits and collection remain outside it.

The simpler alternative, unconditional escape emission based on `TERM`, cannot
establish actual support through SSH/tmux. Auto mode uses a real capability reply;
`on` is an explicit unverified override and `off` retains ordinary painting.
The terminal diagnostic view displays the reason. No package dependency or
scheduler query was added. Configuration remains compatible through one optional
field with an auto default.

## Regression and independent review

Command:

```text
.venv/bin/python -m pytest -q tests/test_terminal_sync.py tests/test_raw_terminal_input.py tests/test_screen_cell_painter.py tests/test_terminal_curses.py
169 passed in 2.62s
```

Tests cover capability statuses, arbitrary reply fragmentation, unsupported output,
timeouts, output failure, nested/unchanged frames and reset on RuntimeError,
KeyboardInterrupt and curses errors. The existing real-curses/PTY test now replies
to the real probe, observes frame boundaries, preserves embedded-shell keyboard
input and checks balanced sequences after exit. Its original mouse and keyboard
behavioral assertions remain intact. This PTY acts as a protocol peer, not as a
qualification of a particular graphical terminal emulator.

Independent reviewer `review_qualification` found that a delayed or duplicate
response could be forwarded into the embedded shell after the pending-probe flag
cleared. The fix retains ownership of recognizable replies after a probe was sent,
without enabling synchronization after timeout. Dedicated late/duplicate tests and
the real embedded-shell PTY path verify the correction.

## Cost and remaining qualification

A supported changed frame adds exactly 16 control bytes; auto negotiation adds
one 9-byte query. One hundred unchanged frames add no synchronization traffic.
The implementation records frame count, emitted control bytes and maximum region
duration. No measured visual improvement is claimed. Real terminal tearing
observations need interactive access; they remain distinct from timing and
protocol tests. SSH latency is not
removed by synchronization. The text `--watch` path retains its existing painter.

See [configuration guidance](../../../guides/synchronized-output.md).

### Controlled local PTY cost

A serialized 3 × 5,000-frame comparison writes the same 2,048-byte payload to a
real raw local PTY and drains it independently. Median wall cost per frame is
7.56 µs for the original flush, 10.03 µs with the disabled guard (+2.47 µs), and
20.36 µs with explicit enabled framing (+12.80 µs). Enabled framing adds exactly
16 bytes per changed frame (0.78125% on this fixture). The raw source hash,
CPU including the reader thread, individual repetitions and executable fixture
are retained in `W19-pty-cost.json` and `benchmark-terminal-sync.py`.

This measures local write/flush overhead, not terminal-emulator tearing, SSH or
tmux behavior. Existing negotiation and actual outer-PTY tests establish the
control sequence behavior; human visual/emulator qualification remains external.
Final integrated regression after W18's event-loop edits remains required.

### Actual multiplexer qualification

`qualify-terminal-multiplexer.py` ran the actual curses application and embedded
shell through tmux 3.5a in auto, off and explicit-on modes. All three preserved
the initial Jobs frame, exact shell input, resize and normal exit. Auto received
no support response and expired to ordinary painting; explicit on emitted frame
boundaries, without claiming the outer peer supported them. Diagnostic snapshots
and source hashes are in `W19-tmux.json`. The outer endpoint is a protocol test
peer, so these results do not establish visual tearing behavior.

The unprivileged tmux binary came from Debian's `tmux_3.5a-3_amd64.deb`, SHA-256
`e6b6aa51780044e2c4a0e618c33f832b70ec80caa30303e6c254a0c851b5af78`.
No system installation or user tmux server was changed. The fixture uses its own
temporary socket and removes its server on completion. An initial fixture waited
for an inherited prompt that tmux did not preserve; the final assertion checks
the actual shell's exact output file instead. No production behavior was changed
to satisfy the fixture. Representative graphical-terminal/manual observations
remain an explicit external qualification gate.
