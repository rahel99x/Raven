## Complete path and design review

`raven`, `ravenl` and `ravenh` route `mcp` through the existing CLI. The optional
`mcp` extra installs maintained Python SDK 2.3.x (2.3.0 qualified here), while
normal startup and the worker kernel remain standard-library-only. The SDK owns
JSON-RPC, negotiation, tool schemas and cancellation. Stdio is the only exposed
transport; no remote authentication surface is introduced.

Five tools reuse the W23 read-only index: list attempts, read capture receipts,
read bounded logs, query evidence, and inspect retained timeline rows. Index and
expected project are fixed at startup. Every SQL request checks project metadata
on its **same** read-only connection before executing SQL; a separate check would
introduce a scope race. Traversal/symlink paths are rejected. The SQL authorizer
forbids writes, attached databases, extension loading and unqualified functions.
No tool accepts shell commands, scheduler actions or filesystem paths.

Reads dispatch through `mcp-evidence-read` on the existing verified Heavy worker.
Light reports deferral; it never silently performs SQL on a login host. The
server captures the process router before entering its one-thread executor.
Requests are serialized; at most eight may run or wait. Each query has limits of
100 rows, 64 KiB evidence, one second and 200,000 SQLite VM steps. The worker adds
CPU/RSS and ten-second wall limits; a twelve-second server deadline includes
queue time. Physical request lines are capped at 128 KiB before SDK parsing.
The complete serialized tool result (including its duplicated text/structured
representation) is capped at 256 KiB, and the whole JSON-RPC response at 512 KiB.
The 64 KiB figure measures SQL evidence consumption, including lookahead, rather
than wire bytes. `source_id` is bounded to SQLite's signed 64-bit positive range
in both runtime validation and the published schema.
Cancellation sets the worker token and never replays a read automatically. The
single executor retains client ownership while draining newly admitted tasks;
next admission follows their terminal/reaped state. An unverified two-second
drain poisons that server session until reconnect.

Opaque HMAC cursors bind the exact tool, arguments, startup scope and index
generation. A changed index/query or process restart invalidates the cursor.
Pagination stops at 10,000 rows. Byte-limited results remain partial and preserve
available bytes; oversized rows are not silently truncated. Results expose
capture/source digests and row/line identity, and label log/plugin/receipt text
as untrusted evidence rather than server instructions.

The simpler alternative was a hand-written JSON-RPC loop, but it would duplicate
negotiation and cancellation semantics. The SDK adds optional installation weight
without changing the dependency-free ordinary wheel. A generic filesystem tool
would be simpler for a client but would defeat the startup evidence grant.

## Actual validation

`RAVEN_MCP_QUALIFICATION_EVIDENCE=docs/implementation/review-2026-10/evidence/W41-actual-stdio.json python -m pytest -q tests/test_mcp_evidence.py`
passed **14 MCP tests** in 3.93 seconds after the final review fixes. The independent SDK client started a real Raven Heavy local
worker over actual subprocess stdio, negotiated **2025-11-25** in legacy mode
and **2026-07-28** in automatic mode, invoked all five tools, rejected mutation
SQL, observed an actual running task PID, cancelled that task, verified its
terminal publication and reaping before the next request was admitted, then
verified the next response belonged to the new query. Both protocol modes also
verified that stdio disconnection reaped the owned Heavy worker. Tests also cover
scope mismatch, symlinks, extra fields, bounds, large retained logs, byte fidelity,
cursor tampering/query changes/restart/index changes, source integer bounds,
committed worker-result immutability, whole-message limits and uncertain-drain
refusal. The fixture only observes real worker publications; it does not inject
results or replace task execution.

This is protocol and local process qualification over explicit synthetic exported
evidence. It is not a live-site, GPU, human MCP-host or production remote service
claim. The SDK is qualified on Python 3.12 in CI; standard-library kernel tests
remain in every supported Python job. Installed-wheel help is exercised through
all three entry points without requiring the SDK. Final integrated revision
checks remain recorded separately.

Usage, installation, admission, pagination and recovery are documented in
[mcp-evidence.md](../../../guides/mcp-evidence.md). No permanent dashboard controls
were added. Deployment with a specific human client or remote transport requires
its own qualification; neither is claimed here.
