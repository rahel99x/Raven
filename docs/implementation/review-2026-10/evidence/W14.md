# W14 — Real Slurm qualification

Source A-01. Baseline `33316a08bd583a242356c7722a21c10e00cff21b` with revision/content
hashes recorded for each exercised working-tree snapshot. This package provides
real scheduler evidence; it does not turn a container into production-site or
physical-device qualification.

## Design and actual environment

Docker 28.4.0 was available through its local Unix socket. The fixture builds
unmodified upstream Slurm source with a pinned SHA-256, a digest-pinned Debian
base and the signed 13 October 2026 Debian package snapshot. It retains TLS and
package-signature verification. Source hashes obtained through TLS are not a
vendor signing claim. Compiler timestamps mean the image is not claimed to be
byte-for-byte reproducible; each exercised image and installed package list is
recorded.

A uniquely named disposable privileged container owns controller, compute daemon,
accounting daemon, MariaDB, synthetic `raven` user and `labx` account. Its network
is internal, with no published host ports; checkout is read-only and only a new
evidence directory is writable. Cleanup addresses only this invocation's named
container/network. No site credential, production controller or user job is used.
The simpler alternative, fake CLI transcripts, remains useful for fast unit
regressions but cannot validate scheduler lifecycle and accounting behavior.

The fixture selects task/none, proctrack/linuxproc and Linux process accounting.
It does not establish cgroup accounting or resource enforcement. Older releases
need their v1 plugin loaded without activating controllers; newer releases can
explicitly disable that plugin. Controller/compute resources are deliberately
small declarations, not physical benchmark claims.

## Maintained version and compatibility matrix

Upstream's current documentation and download index were checked on 17 October
2026. Slurm 26.05.5 (13 October release) is the maintained smoke candidate.
Requested historical lines remain pinned as compatibility candidates:
23.02.8, 23.11.11, 24.05.8 and 24.11.7. Their presence does not imply current
vendor support. `scripts/slurm/versions.json` retains hashes and source links.

All five versions completed the real vertical lifecycle on 18 October 2026,
including actual Raven readers, retained details/submission/steps, numeric job-ID
reuse and exclusion of the recycled submission from the original identity.
The [matrix receipt](W14-reader-matrix.json) binds each invocation to source
hashes, image ID, UTC timestamps and the exact command. Full command receipts,
stdout, stderr, configuration and package lists are retained under
`tests/fixtures/slurm/recorded/<version>/final/`.

Lifecycle timing excludes fixture startup and cleanup; driver timing includes
them. These are integration durations, not controlled performance comparisons.
Unsupported historical accounting fields remain explicitly unavailable.
Controller-side cancellation filters were exercised on 23.11 and newer;
23.02 does not offer the required atomic API.

The final matrix reused recorded exact-version compiled images and supplied the
current entrypoint from the read-only checkout. It is **not** evidence of a clean
build from the final digest-pinned Debian snapshot Dockerfile. The source-built
service behavior and image identities are established; a clean hosted build on
the delivered revision remains a CI qualification requirement.

Actual failures informed fixture and parser corrections without relaxing
production ownership checks. The apt CA mount needed public read permissions for
`_apt`; TLS checks stayed enabled. Requeue exposed Slurm's default 120-second
delay; the disposable configuration selects one second and a ten-second
credential expiry. Historical versions require an inactive v1 cgroup plugin.
Slurm 23.02 uses `meta.plugins` rather than `meta.plugin`; that spelling now
permits capability detection while preserving its unsupported-parser fallback.
Historical step rows omit User, which Raven accepts only beneath a uniquely
verified parent, with contradiction, duplicate and time-window checks.

A retained controller restart does not reset numeric IDs. The recycle fixture
therefore starts a new, owned empty StateSaveLocation while retaining accounting;
it proves reuse instead of labeling requeue as reuse. Finally, this host's Docker
vfs driver copied entire images for tiny overlays. Exact task-owned overlays and
cache references were removed, and the runner now mounts its current entrypoint
read-only with the existing tini reaper. No global pruning was used.

## Evidence and safety checks

Every recorded command includes argv, exit status, seconds, stdout/stderr paths
and SHA-256. Config, version, help, legacy and JSON outputs preserve synthetic
account/resource fields, arrays, paths/names with spaces and literal `=` bytes.
The lifecycle additionally exercises exact retained details/submission/step
lookups and numeric ID reuse by a clean generation of its own controller while
keeping accounting. That clean-generation action is forbidden outside the
owned disposable fixture. The final per-version manifests determine which
checks passed; requeue is not mislabeled as numeric-ID recycling.

Cancellation source review found a critical version difference: 23.02's client
cannot provide the atomic controller-side REQUEST_KILL_JOBS filter guarantee.
23.11 and later sources send one controller request with exact name, UID and
job IDs, with no per-job fallback on RPC failure. The maintained live check
showed wrong-name and wrong-UID requests left the held job pending; matching
filters cancelled it. W17 enables only versions with actual qualified evidence,
not every version whose source appears compatible. `scontrol --version` is a
client version; the controller's version comes from `scontrol show config`.

The real-slurm workflow uses a bounded maintained-version smoke on relevant
trusted repository PRs and a nightly/manual five-version matrix. Privileged
fixtures are excluded from fork PRs; no secrets are passed. Each run uploads
source-bound diagnostic artifacts, including failures. Hosted execution still
needs to occur on the delivered revision; this local work did not publish or
dispatch a workflow.

Physical GPUs, true multi-node performance, production SSH, production account
policy and heterogeneous allocations remain separate gates. No simulator or
single-container measurement closes them. See the [reproduction guide](../../../guides/slurm-qualification.md).
