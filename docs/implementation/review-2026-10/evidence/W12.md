# W12 — Shared framing with explicit channel policies

Sources: A-06; W12-R01–R08. Baseline `33316a08bd583a242356c7722a21c10e00cff21b`;
candidate is the uncommitted integrated working tree.

## Baseline and smallest complete extraction

All three modules repeated network-order length prefixes, receive buffering,
partial frames and partial-write advancement. Existing fragmentation tests passed
before the move. Shared `FramePolicy`, `Decoder`, `frame` and `write_pending` now
live in `raven.transport.framing`, with a public `raven.framing` import shim.
Channel modules retain their own serializer/parser, public decoder interfaces,
error classes and admission semantics. Output queue ownership and recovery stay
with their existing clients/selectors.

A single JSON codec with the terminal's largest budget would simplify signatures
but silently broaden worker/allocation acceptance. It was rejected. The shared
layer only frames bytes; domain validation and canonical evidence hashing remain
separate. Existing worker build-digest enforcement intentionally rejects mixed
executables; unchanged v1 wire fixtures remain readable byte-for-byte.

| Policy | Frame | Receive queue | Additional policy |
| --- | ---: | ---: | --- |
| Worker | 1 MiB | 8 MiB | eager header checks; bytes-only feed; existing depth/string/record policy |
| Allocation | 1 MiB | 1 MiB + 65,540 bytes | existing allocation depth/ownership policy |
| Terminal | 8 MiB | 8 MiB + 65,540 bytes | 32 levels; 1,000,000 document nodes |

Duplicate keys, NaN/Infinity, exponent overflow and invalid UTF-8 are rejected.
Terminal metadata/input are validated before process creation/enqueue. Receive
budgets use memoryview byte size. Partial sends yield counts only after queue
advancement, retaining exact tails through backpressure. Decode compacts once per
drain. Worker commit and client receipt publication reuse immutable canonical
bytes for the hash and retained length; receipt hashing itself is unchanged.

## Verification and performance

The existing 61 characterization tests passed before and after extraction. The
289-test focused regression and subsequent 191-test protocol/terminal run are
recorded in W11. Generated tests cover every policy, partial writes, invalid and
oversize/empty frames, bounds, and canonical round trips. Captured baseline wire
fixtures cover legacy/new framing compatibility; unsupported mixed worker build
admission continues to fail by design.

`scripts/benchmark_framing.py` measures identical encode/decode fixtures in fresh
processes, keeping timing runs separate from tracemalloc and reporting process RSS
in KiB independently. The first controlled comparison found worker throughput
11,481.6 → 10,674.8 frames/s, allocation 10,828.3 → 9,972.6 frames/s, and terminal
40,340.7 → 8,247.7 frames/s. The terminal regression was unacceptable: duplicate
full-grid Python walks were removed. The receiver still validates all structure,
duplicate keys and finite JSON; it walks containers instead of pushing every
scalar cell, and sender JSON encoding enforces JSON/UTF-8 constraints.

The optimized controlled rerun is recorded in [W12-comparison.json](W12-comparison.json)
and its raw source-hashed artifacts. Baseline/current throughput is 11,242.7 /
10,579.3 frames/s for worker (-5.9%); 10,878.1 / 8,939.9 for allocation (-17.8%);
and 40,800.5 / 22,094.4 for terminal common documents (-45.8%). Additional time is
5.58, 19.93 and 20.75 microseconds per frame respectively. The terminal path is
2.7 times faster than the first hardened implementation but still slower than the
original unchecked decoder. An 80-column, 24-row fixture with one styled segment
per cell measures 1,642.7 / 833.1 frames/s (-49.3%), or 0.592 ms additional
encode/decode work per frame. It preserves every cell; no coalescing or fidelity
loss hides the cost.

Python peak allocations changed by +485 B (worker), +23,866 B (allocation),
+10,316 B (terminal common), and +27,146 B (grid). Whole-process RSS changed by
+128, +68, +256, and +720 KiB respectively. All timed fixtures reported zero block
I/O. These are measurable regressions from shared dispatch plus stronger
validation, accepted here for correctness and made visible for subsequent
optimization. No scheduler-load, remote-throughput or end-to-end UI latency gain
is inferred. Final integration must retain the source hashes or repeat affected
measurements if the framing/validation path changes.
