# W07 — Scoped SSH reuse

Source: review A opening SSH assessment. Baseline:
`33316a08bd583a242356c7722a21c10e00cff21b`. Candidate integration source is recorded
in [source hashes](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W04-W07-source-hashes.json).

## Verification and implementation

Confirmed: `raven_launch.configure_placement` explicitly used `control=False`,
while legacy reuse used `%r@%h:%p` without proxy/security-option identity or a
verified private socket directory. The external log pager also discarded
configured port/proxy/host-key options.

Managed placement now enables the shared backend's reuse. `ssh_control.prepare`
asks OpenSSH to resolve Host/Match/Include itself, using a temporary include wrapper
whose defaults follow original configuration. Client hostname/boot, effective target/user/options and
configuration are hashed into an owned `0700` control directory. Explicit
ControlMaster=no and ControlPath=none opt-outs are preserved. When enabled, custom
socket paths are narrowed to Raven's private scope. The pager now uses this same
transport rather than reconstructing an incomplete SSH command.

The simpler target/user/port hash fails when proxies or security settings differ.
A custom SSH-config parser would duplicate OpenSSH semantics. Resolving once and
caching forever would reuse an old authenticated connection after a security
configuration edit. Therefore each request performs one bounded local `ssh -G`
process; measured below. It sends no scheduler query. User security/host-key
settings remain intact. If scoped resolution is unavailable, reuse is explicitly
disabled and `control_diagnostic` records why; an unsafe private directory is an
error, not a permission repair.

No retry was added to `run` or `call`: any failed command, including a mutation
with a lost acknowledgment, is sent once. OpenSSH reconnects on the next request
when its socket disappears. Default idle cleanup is OpenSSH ControlPersist=600;
user persistence policy is respected. Resolution files are removed immediately;
Raven does not terminate a possibly shared live master.

## Acceptance evidence

`tests/test_ssh_control.py` covers differing targets/users/ports/proxies/host-key
policy/agent settings; equivalent scope reuse; explicit option and included-config
opt-outs; changed configuration isolation; custom-path narrowing; unsafe directory
rejection; no replay on ambiguous failure; pager security preservation. The prior
local-shell test now selects `-F none` to avoid depending on host SSH configuration
while preserving its behavioral assertions.

Focused result with existing SSH/plugin workflow: **13 passed, 33 deselected**.
The combined config/SSH/background-Heavy run also passed (176 tests before the
additional pager regression). Full integrated evidence is reported separately.

[Real loopback OpenSSH qualification](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W07-loopback-ssh.json) used generated
Ed25519 client/server keys and strict client host-key checking. Forty-eight real
remote commands ran in interleaved disabled/enabled groups of twelve:

| Measure | Separate connections, two groups | Reuse, two groups |
| --- | --- | --- |
| Authentications per 12 commands | 12 / 12 | 1 / 1 |
| Mean latency including first authentication | 84.44 / 83.48 ms | 17.64 / 16.72 ms |
| Median latency | 84.06 / 83.78 ms | 11.09 / 10.36 ms |
| Reaped client-child CPU | 0.1317 / 0.1261 s | 0.1107 / 0.1011 s |

The local `ssh -G` cost is included. CPU is RUSAGE_CHILDREN of the driver and
excludes the still-running sshd and persistent master: it is **not total process
-tree CPU**. No network-byte, billing or energy claim follows. Scheduler command
count and request freshness are unchanged; each requested command still executes.

The fixture closed its own master, then observed exactly one authentication for
successful reconnect. A real remote append followed by exit 255 occurred exactly
once. Socket mode was `0600`; containing directory `0700`. The isolated fixture
server used StrictModes=no solely because this sandbox remaps `/tmp` ownership to
uid 65534; all key files were private and the client still verified the exact host
key. This does not qualify production SSH ownership or a target cluster.

The reproducible harness is `scripts/qualify_ssh_reuse.py`; it stops only its own
loopback server/connections and deletes its generated private keys. See the
[SSH guide](../../../guides/ssh-connections.md) for normal and remapped-container
commands. Root-only site configuration, production proxies, multi-node/GPU and
cluster access remain separate qualification gates.

## Review and rollout

Review found and fixed `ssh -G` omitting ControlPath=none, explicit `-S` overriding
the narrowed path, shared mutable argv construction, and pager option loss.
Configuration identity is recalculated on each invocation. The no-replay behavior
was checked both with injected ambiguous failure and the actual remote mutation.
No config schema/state migration is required. Existing explicit opt-outs survive;
update through the normal installer, and set ControlMaster=no for rollback of
reuse behavior. A short host-local temporary directory is required for Unix
sockets; a shared or excessively long TMPDIR is not qualified by loopback tests.

Final controlled rerun includes client hostname/boot socket isolation. An earlier accidentally overlapping timing run was discarded; only the serialized rerun is retained above.


## Concurrent test isolation

The final Python3.14 paired regression exposed a fixture that incorrectly required
the shared per-user SSH directory to contain no temporary configuration from
other concurrent clients. `e3c7183` redirects only that test to its own temporary
root. Real trust checks, OpenSSH configuration resolution and wrapper removal
remain exercised, and every prior sharing/ownership/permission/option assertion
is retained. Deleting peer files or serializing away the condition was rejected.
The complete 12-test SSH module passed on each Python3.10–3.14 interpreter;
[the receipt](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/W07-fixture-isolation.json) records the failure, focused results
and independent review. Production code is unchanged.
