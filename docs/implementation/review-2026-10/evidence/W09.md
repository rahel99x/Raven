The source proposal is A-20; its exact subrequirements remain in

## Design and implementation

Retain the dependency-free inventory and add an explicit `policy` command for
full source revision, installed version, exact `vVERSION` tag and identical
bundled source bytes. `verify_release.py` delegates cryptography to GitHub's
maintained Sigstore verifier and requires caller-selected repository, workflow,
signer revision and source revision. It rejects self-hosted-runner provenance
under the declared release policy. No identity supplied by the artifact chooses
its own trust root. `--plan` explicitly reports signatures unverified.

The simpler alternative, unsigned checksums alone, is already implemented but
cannot authenticate a publisher. Implementing another signing stack in Raven
would add dependencies and maintenance without improving this boundary.
Inventory work remains bounded by its existing artifact/member budgets; crypto
verification has a 90-second per-artifact timeout and never invokes a shell.

`release-candidate.yml` calls the complete existing Python compatibility and
packaging workflow, uses its exact tested artifacts, checks policy, and can
attest/verify them. Manual dispatch defaults to no attestation. Authorized tag
pushes and explicit future attestation dispatches can create provenance; the
workflow neither creates tags nor publishes releases. No workflow was dispatched
and no repository tag, release, or provenance record was published here.

## Validation and review

`python -m pytest -q tests/test_release_inventory.py` passed **38 tests** on
Python 3.12, including tampered archive/member records, wrong expected version,
tag and revision, differing source bytes, exact verifier identity flags, a
non-writing verification plan and propagation of cryptographic-verifier failure.
The verifier-call tests simulate its process result; they are not a real signed
artifact verification. Later focused combined qualification run: 42 passed.

Separate diff review checked that an unsigned source claim is not promoted to
authenticated provenance, failed verification cannot fall back, tokens do not
reach fork PRs, and artifacts are not rebuilt after qualification. The workflow
still needs hosted execution against the delivered revision. Source/member
checks are added to ordinary CI, so a changed package boundary cannot silently
ship different wheel and source contents.

The local `gh` does not provide `attestation`; no GitHub OIDC token or signed
Raven bundle exists in this task, and new external publication is not authorized.
Unblock the cryptographic/hosted gate with an authorized workflow run and a
current GitHub CLI. Do not represent old unsigned 7.0.0 artifacts as signed.
No performance gain is claimed: this is release correctness work, with existing
bounded inventory inspection reused. See the [release procedure](../../../guides/release-inventory.md).
