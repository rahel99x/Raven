# W39 — Administrator-managed shared host observations

Source A-10; baseline `33316a08bd583a242356c7722a21c10e00cff21b` has a
same-user shared-query cache, not a multi-user daemon. The delivered optional
milestone reuses W38's versioned bounded protocol, selector, kernel ownership,
cursor/gap behavior and the managed collection ledger/cache. It never changes
ordinary Raven startup or installs an administrator service automatically.

## Design and authority

Linux `SO_PEERCRED` authenticates each connection. A protected policy separately
maps that exact host UID/login to own-user, explicit Raven-project, named-account
or site visibility. A Unix socket group only permits connecting. Filtering occurs before
field allowlisting and serialization; commands, work directories, logs, configs,
raw scheduler text, global row counts and global sequence counters are absent
from ordinary-user projections. Cache identities bind UID, grant and policy
generation. Missing/ambiguous scheduler ownership fails closed.

The simpler alternative is keeping independent per-user readers and their existing
cache. That requires no privileged aggregate view and remains the default. The
shared service adds administrator deployment and policy complexity; its value is
potentially fewer native source reads on a busy login host. It is justified only
after the site's visibility and resource policies are verified. It provides no
arbitrary file read, shell command, submission, cancellation or allocation action.

The fixed reads are bounded `squeue --json` and recent `sacct --json --allusers -X
-S now-24hours`. One background collector uses the stricter source/site cadence;
clients cannot trigger reads. `GovernedBackend.observe` explicitly preserves the
recurring-read admission path and cancellation, rather than using the fresh
review-command path. Recorded structured parser coverage applies; unsupported or
ambiguous responses retain prior source data with an explicit stale diagnostic.
Scheduler `PrivateData` still constrains what the service identity can see.

## Project authorization correction

Independent coverage review found that lab-account grants did not satisfy the
handoff's distinct research-project requirement. The protected policy now maps
exact Raven project IDs to native parent attempts and grants project IDs to each
principal. Membership binds cluster, job/task/component ID, submission/start Unix
seconds and restart count. Missing/unset native fields abstain; restart zero is
never inferred. Array ranges and step IDs cannot become parent memberships.
Pending/configuring queue start predictions never authorize projects; only
running, suspended or completing queue attempts can match. Accounting rows are matched by normalized ID because the existing parser sorts
completed records; positional zipping would bind the wrong attempt.

The simpler alternative, treating a Slurm account as a project, is incomplete:
two independent projects can share LabX. Name/path/comment matching would trust
user-controlled descriptive metadata. The bounded administrator-reviewed map
adds maintenance effort but gives an explicit authority source without arbitrary
file access or a new privileged submission service. It permits 256 projects,
64 project grants per principal and 1,024 total exact memberships within 256 KiB.
Automating the site's trusted membership producer remains a deployment gate.

Project grants form a union with own-user/account/site grants. An explicit LabX
grant intentionally reveals both projects. Only granted project labels leave the
service; private attempt indexes and another project's names do not. Membership
changes alter policy generation, discard pending old-authority bytes and clear
caches/replay metadata. The shared module's `tui` command reuses W38's background
reader and shows effective grants/project labels; JSON/watch carries the same
scope and independent source errors. Unknown-identity project omissions are
explicit in coverage metadata and the setup guide.

## Bounds, recovery and diagnostics

Up to 256 configured principals/connections; 2,000 rows per authorized response
list; 8 MiB authorized-view cache; 8 MiB aggregate pending output; 32 reads/s globally
and 4 reads/s per UID, including reconnects. Four concurrent connections per UID prevent one principal
from monopolizing all idle connection slots. Existing frame and slow-peer bounds are
reused. Per-user cache eviction retains bounded identity metadata and signals
replay gaps. Policy replacement clears old authorized views and pending bytes;
malformed policy closes peers and fails closed until repaired. Already delivered
bytes cannot be revoked. Changing socket group or service identity requires a
reviewed restart. No PID-based process adoption or unrelated cleanup occurs.

Queue/accounting timestamps and failures remain independent. The service account's
stderr receives parser diagnostics, policy rejection/generation events and a
bounded health record each minute. Peers receive generic source errors to avoid
disclosing other users' attributes in scheduler error messages. Socket 0660,
directory 0750 and private retained files 0600 preserve separate connection/read
authorities. An independently selected service UID is checked by the client.
