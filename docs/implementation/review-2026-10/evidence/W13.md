# W13 — Versioned schema and validation strategy

Sources: A-06; W13-R01–R08. Baseline `33316a08bd583a242356c7722a21c10e00cff21b`.

## Inventory and decision

The machine-readable schema/runtime inventory is in
[W22-architecture-candidate.json](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/W22-architecture-candidate.json). It records all
published schemas, local reference strings, schema constants, runtime modules
containing those constants, and candidate hand-validator symbols. These are
review associations, not claims of complete semantic equivalence. For example,
`adapter_protocol.validate_manifest` adds executable identity/filesystem checks;
`evidence.validate` adds canonical identity semantics; `runtime_control` adds
mailbox/boot/ownership checks. A general schema cannot replace those actions.

Three options were compared: generated lightweight validator source (extra code
generation/build artifact and drift burden); shared typed contracts that generate
the documentation schema (one narrow source of truth); and full JSON Schema at
runtime (mature semantics, but added dependency/import/hot-path cost). The selected
first migration is the worker control envelope. It is a deliberately small typed
contract, not an incomplete general JSON Schema engine. The runtime remains
stdlib-only; independent `jsonschema` is development-only validation.

`protocol_contracts.CONTROL` specifies hello, placement, admit, cancel, ack, status
and shutdown envelope names/types. The generated `worker-control.v1.schema.json`
is drift-tested. Existing domain validators still check task policy, exact
placement, build, nonce, resource and ownership semantics. Unknown actions and
outer action fields are rejected. New descriptive data must be placed under
`extensions`; it is never interpreted as an action.

## Compatibility and migrations

No persisted format or protocol major changes in this extraction. Existing data
therefore follows an identity migration: validation does not mutate the caller,
and canonical encode/decode round trips preserve evidence. Unsupported major
versions fail explicitly. Future migrations must be separate versioned bounded
converters with fixtures; no permissive implicit migration was added.

The independent schema corpus includes integer literals, integral floats,
nonintegral floats, booleans, strings, arrays, objects and missing/unknown fields.
JSON Schema accepts mathematical integral floats; envelope validation matches
that definition. Existing handshake domain checks still require integer wire
literals. The generated schema has no references; existing schema inventory
records local refs without fetching remote resources. Framing enforces input
size, depth and string/record budgets before control dispatch.

## Validation and measured cost

`tests/test_protocol_contracts.py` tests generated drift, all seven operations,
independent schema/runtime structural agreement, explicit extensions, major
version refusal and nonmutation. It is included in the 289- and 191-test focused
runs in W11. The latter includes the integral-float correction.

[W13-contract-benchmark.json](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/W13-contract-benchmark.json) records the final
controlled 5,000-call, three-repeat envelope comparison after the parity fix.
Typed validation took 0.00624–0.00659 s; full JSON Schema took 0.618–0.627 s.
Verified contract import cost was 0.00740 s versus 0.03511 s for jsonschema.
The 16,728 KiB RSS is the **whole process with both implementations imported**,
not a per-dependency memory saving. The contract source hash is retained. The
fixture excludes domain validation and network I/O; later changes to this path
require rerunning this measurement.

Coverage expands incrementally; the other published schemas remain documented
manual/domain contracts. Loading every schema on every message was rejected.
