# W06 — Attempt-safe metric archives

Source: A-05. Baseline: `33316a08bd583a242356c7722a21c10e00cff21b`.
Disposition: implemented for observed/verified identities, with scheduler observability and live qualification limits below.

The baseline path sanitized only a job number. Requeues/reused IDs therefore shared a JSONL file, and in-memory series were not cleared when a running job's attempt changed without disappearing from the queue. The existing archive-generation guard did not fix on-disk attribution.

`series_identity.SeriesIdentity` now binds connection/profile/user scope, exact unsanitized job/array/heterogeneous identity, cluster, submission/start evidence and verified restart count. The optional trusted-caller API `Store.bind_series_attempt` can represent a verified retained run identity, but it has no production caller and is not counted as a delivered retained-run reader. The production path binds scheduler observations through `Sampler.src_details`, including qualified historical accounting after a job leaves the controller. File names use a reversible bounded job component and SHA-256 over the complete identity; sanitized-name collisions cannot merge records. JSONL sample representation and timestamp precision are unchanged.

Scheduler verification requires matching job identity, submission time, start time and restart count. Submission/start timestamps alone have insufficient resolution to distinguish rapid requeues. Missing or contradictory evidence therefore uses a random session identity. These provisional files remain readable in that session but never become evidence for a later session by inference. Details verification starts a separate verified stream; it does not relabel previously unknown samples. Arrays and heterogeneous component records match their explicit scheduler identity fields.

The sampler captures immutable identity before acquiring measurements and checks it before publishing. Persistence queues capture the destination path at enqueue time. Background archive requests likewise retain their requested identity/path, and reject stale merges. An attempt change invalidates native series, rates, GPU means and prepared publications. Reports copy identity state, so a delayed export cannot switch to a newly selected attempt. Existing bounded archive readers, quotas and background executors remain in use.

The existing first selected-job detail request is ordered before its initial native sample when possible, with no additional scheduler command. Failed or incomplete inspections still permit provisional CPU/memory data; they cannot suppress sampling indefinitely. GPU diagnostics distinguish unattributed old rows from verified current-attempt graph readiness.

The simpler alternative, `(job, start_time)` filenames, is insufficient for same-second restarts and multiple sites. A process-local generation fixes some callback races but cannot survive a restart. A new binary format or database is unnecessary for this identity repair; those remain separate W24/W25 work.

Regression coverage includes same-ID/same-time different restart counters, same-state requeues, delayed writes, late callbacks, restart/reopen, scope separation, sanitized collisions, unknown identity, non-attribution during verification, partial JSONL, report isolation, preserved fractional timestamps and cold-loader concurrency. A 35-example Hypothesis property generates independent old/new timestamp sequences, duplicates, delayed stale callbacks and reopen operations, asserting exact new-attempt values without cross-generation data. Existing concurrency tests now create files at captured paths; all ordering, lock-availability and fidelity assertions remain.

## Final audit correction: reopen after controller purge

The final coverage audit reproduced a production integration gap: selected completed-job accounting retained submission/start/user/cluster evidence but dropped the qualified JSON `restart_cnt`. Earlier reopen tests supplied details directly and therefore did not establish the real `Sampler` → fresh `Store` → historical reader → archive/report route. A controller-purged completed job could not regain its verified native recordings after restart.

The smallest correction carries the optional, validated restart counter through the existing bounded selected-job accounting query. It does not add a query, a manifest database, an inferred zero, or a timestamp-based attempt guess. Qualified JSON observations validate integer type and the same ten-digit bound as the durable identity; malformed counters fail visibly without retrying a weaker parser. The legacy ten-column command remains compatible, but missing restart evidence explicitly reports why attribution is unavailable. Original recordings remain preserved. A retained launch-manifest reader remains a possible future source of proof, not an implemented dependency of this correction.

`tests/test_completed_series_identity.py` now creates recordings through queue acquisition, selected-job verification and persistence, closes the original store, replays completed accounting with the controller record purged, and opens both a fresh interactive store and a private report. It covers JSONL and compact files (including discovery under the default JSONL preference), unavailable log paths, missing/different/invalid restart counters, and legacy accounting. CPU/memory samples are recovered exactly when proof matches; weaker or contradictory proof cannot borrow an old stream. These are deterministic replays of captured real Slurm 26.05.5 output, not a new live purge/reopen qualification.

## Final regression correction: Quick Advisor and lifecycle fixtures

The integrated discovery gate found four obsolete Quick Advisor fixtures still placing samples in `series/JOBID.jsonl`. They now acquire an actual scoped state owner and bind scheduler submission/start/cluster/restart evidence before creating the exact attempt file. The existing sample-count, unlocked background I/O, bounded-tail and FIFO-refusal assertions remain intact. A separate negative test preserves a legacy file and confirms that its rows are never attributed to the current job.

Review of that consumer also found a real integration gap: its publication key omitted the verified restart token, and a compact recording could be parsed as JSONL and silently contribute no samples. Quick Advisor now captures `SeriesIdentity` with the initial job snapshot, retains that identity through file acquisition, rejects an attempt change with an explicit retry error, and compares the same immutable identity before UI publication. A same-time restart during acquisition and after a worker completes are both covered. The reader discovers compact counterparts even under the JSONL preference and uses the existing verified block decoder. It preserves the detached UI cache, exposes corruption/limited-prefix diagnostics, checks cancellation between frames and caps cumulative decoded bytes before decompression to the Advisor's existing read budget.

Forecast integration fixtures had also mocked `cli.os.getuid` on Python's shared `os` module, inadvertently changing the filesystem trust check's actual UID. The mock is now local to the CLI namespace. Sequential startup tests close their previous session; deliberate malformed-state fixtures are installed offline by a short-lived real owning Store after normal shutdown. Refresh persistence tests flush, close and reopen their actual owners. No production ownership or trust check was relaxed.

Validation: **482 passed in 4.47 seconds** across the affected archive, block/retention/maintenance/settings, native telemetry, report, state, Quick Advisor, forecast and refresh modules. `state-final-advisor-validation.json` records the full command and source hashes. An earlier narrower selection passed 262 tests in 1.64 seconds. These checks use deterministic synthetic samples and real local files/workers; they do not establish live scheduler or GPU behavior.
