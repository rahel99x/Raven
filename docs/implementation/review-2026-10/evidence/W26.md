# W26 — Bounded streaming changes

Source: A-17, reconciled against baseline `33316a08bd583a242356c7722a21c10e00cff21b`.
The baseline already retained attempt-scoped observations and a notification
center; it had no bounded live change detector. This is an experimental
capability, not a demonstrated production defect or diagnosis engine.

## Design and complete path

`stream_anomalies.py` implements a 32-observation robust median/MAD baseline,
12-observation warmup and three confirming excursions. RSS has a positive-trend
check. A simpler fixed threshold cannot accommodate each stream's observed
baseline; CUSUM adds another tuning/state surface without a demonstrated use
case, so it was deliberately not added. Numeric state is bounded to 128 LRU
streams and 64 deduplicated episodes. An episode retains its actual window and
states that its cause is unknown. Gaps, declared phases, missing values, uneven
sampling, noisy/constant baselines and physically invalid RSS/GPU values can
abstain or reset warmup.

Store.record observes only W06's verified current attempt after append. Old
attempt callbacks cannot enter the current detector. The notification panel
renders cached evidence text and uses its existing dismiss control; there is no
new permanent toolbar. The monitor does no filesystem or scheduler work and
runs only during ingestion, never in paint. State and alerts are deliberately
session-bounded; a restart warms up again, while retained recordings remain the
repeatable evidence source.

The read-only `telemetry-anomalies` Research operation follows the existing
admitted Heavy worker, cancellation and execution-receipt path. The indexed
recording converter selects one exact source/capture/attempt/stream, preserves
CSV row and digest provenance and refuses ambiguous inputs. The guide and
schemas specify the producer format. A memory forecast requires an explicit
RSS limit with the same measured scope; live monitoring does not infer a
per-rank limit from a whole allocation. Output is an interval of remaining
seconds with units, residual sensitivity uncertainty and an observed-span
validity horizon. It is not a calibrated confidence interval or precise date.

## Validation and measurements

Focused command after independent review:

```bash
.venv/bin/python -m pytest -q tests/test_signal_inputs.py tests/test_stream_anomalies.py tests/test_phase_alignment.py tests/test_notifications.py tests/test_attempt_series.py tests/test_diagnostic_trials.py
```

**131 passed in 12.93 s.** This includes an actual local WorkerClient admission,
existing export/index conversion, notification dismissal, attempt rollover,
physical-invalidity abstention and preserved retained-source provenance.

`W26-W32-evaluation.json` records fixed-parameter held-out synthetic seeds
1000–1019 across steps, leaks, stalls, stationary and noisy controls: 60/60
positive traces detected, median 2 s delay, 0 false alerts in 12,800
observations. These are synthetic fixtures, not site false-positive estimates.
The evaluation script records source hashes and all trial outcomes.

Controlled fresh-process scaling artifacts are `raw/W26-W32-{128-1,512-4,1024-8}.json`.
Median detector cost was 0.994, 16.229 and 63.257 ms respectively for
128×1, 512×4 and 1,024×8 observations/features. Python allocation peaks were
10,840, 61,788 and 148,500 bytes. Full process RSS includes fixtures and both
algorithms, and is not attributed exclusively to detection.

`raw/W26-live-monitor.json` compares identical 6,144 observations across 128
streams with bounded retention alone versus retention plus the live monitor:
median 1.985 → 84.751 ms (**13.47 µs additional CPU-scale work per observation**),
Python peak 296,209 → 794,808 bytes; 4,096 detector points retained. Process RSS
was 14,976 KiB for the process containing both variants. CPU and wall values are
separately retained. This is an explicit additional cost for detection, not a
speedup. There were no timed scheduler commands or disk I/O in this fixture;
real application freshness and site load remain qualification work.

Independent review found that finite but physically impossible RSS/GPU data
could support an alert/forecast. The implementation now resets warmup and
abstains; regressions are included. Identity, deduplication, bounded state and
no-cause language were also reviewed. Input identity assertions never grant
scheduler authority.

## Qualification

This working-tree implementation remains experimental. Real-job sensitivity,
false-positive calibration and UX freshness require representative authorized
recordings; missing GPU data is not fabricated. Final integrated revision,
full regression and packaging checks are root-owned. Raw benchmark/evaluation
source hashes bind the measured candidate; later changes require relevant
revalidation.
