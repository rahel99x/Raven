# W02 — Legacy parser correctness and diagnostics

Source: A-02 and the opening assessment. Baseline: `33316a08bd583a242356c7722a21c10e00cff21b`. Implementation is in the current review branch; final integrated revision and full gates belong to the parent ledger.

## Verification and design

The baseline reproduced `WorkDir=/scratch/my run` becoming `/scratch/my`, `Command=python train.py` becoming `python`, and an entirely truncated queue reply becoming a successful empty queue. Existing array/group provenance checks already rejected ambiguous optional work directories; those checks were reused.

The implementation recognizes bounded Slurm field boundaries, preserves spaces and embedded assignments, rejects duplicate identity/lease fields, and refuses multiple records in a single-record parser. Known field names prevent arbitrary environment assignments from becoming scheduler fields. Unescaped delimiters remain intrinsically ambiguous: command/group provenance becomes unknown, never a truncated launch recipe. Numeric, state and identity columns are checked before publication. Inputs are bounded to 16 MiB, individual rows to 64 KiB; diagnostics retain counters/reasons rather than private raw rows. Parsing and duplicate removal are linear in input size.

A simpler alternative was to keep skipping invalid rows and show a warning. That still fabricates queue departures. Source-level diagnostics now preserve missing old records during partial updates, publish valid records, reject wholly unusable responses, and expose the reason/count in Sources and existing notifications. Partial coverage does not create failure backoff; complete recovery clears the warning. Empty successful output remains a valid empty queue.

Allocation admission now rejects missing, duplicated or invalid lease fields instead of skipping lease verification. Existing ownership and placement checks remain in force. GPU diagnostics uses the same checked parser rather than quietly succeeding with zero records.

## Measurement and review

Controlled equivalent 10,000-row fixture (1,668,893 bytes), isolated same-host Python processes, three warmups and seven CPU-time samples per process; baseline/candidate/candidate/baseline ordering. Initial baseline medians: **52.02 / 52.16 ms**; initial safety implementation: **78.25 / 85.11 ms**. Python allocation peak rose **13,129,264 → 13,654,702 bytes** (~4%). Peak process RSS was **48,904–49,320 → 49,948 KiB**; this is a separate process measurement, not inferred from tracemalloc. No scheduler/network I/O occurred in this fixture.

The safety checks add CPU work; no speedup is claimed. A subsequent small optimization replaced repeated numeric regex checks with bounded ASCII decimal validation and avoided redundant ASCII encodings; final timing is recorded separately when rerun. The full before/after artifact is `docs/implementation/review-2026-10/measurements/parser-before-after.json`.

Final isolated rerun after the optimization is in `measurements/parser-before-after-final.json`: baseline medians **66.19 / 55.82 ms**, candidate **74.26 / 71.45 ms** per 10,000 rows. The host baseline varied materially, so a precise percentage gain/regression is not supported. Candidate Python peak is **13,654,568 bytes** versus **13,129,264 bytes**; process RSS **50,008–50,256 KiB** versus **48,860–48,936 KiB**. Correctness checks remain a measured CPU cost. The final focused integrated parser/accounting/launch suite passed **566 tests in 22.40 s**; see `W15-focused.json` for source hashes and the full command.

Diff review caught an initially quadratic duplicate-removal path (replaced with sets and one final pass), a GPU diagnostic path bypassing coverage, and missing lease fields in old placement fixtures. Those were resolved without removing the behavioral assertions. Real Slurm record keys containing `:` were added to the boundary grammar. Literal delimiter ambiguity and scheduler-version coverage remain explicit limitations; structured reads in W15 address qualified formats.

Final focused integration: **945 tests passed in 29.70 s** across parser/accounting, managed collection, all four planning packages, existing launch/orchestration/worker paths and UI/setup. Exact command and source hashes: `slurm-planning-focused.json`; raw output: `slurm-planning-focused.log`. This complements, rather than replaces, the final integrated full regression.
