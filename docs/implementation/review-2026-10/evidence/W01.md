# W01 — Atomic tags, pins and notes

Source: A-08. Baseline: `33316a08bd583a242356c7722a21c10e00cff21b`.
Disposition: implemented; final integrated revision and full-suite evidence are recorded in the tranche ledger.

The baseline `Store._save_tags` opened `tags.json` with `"w"`, serialized a live mutable dictionary, and suppressed `OSError`. A failed write could therefore destroy the previous publication without telling the user. The candidate retains the plain JSON format and reuses `ui_state._atomic`: private staged file, file fsync, atomic replacement, directory fsync.

A dedicated writer lock is acquired before copying the latest bounded tag snapshot. Slow filesystem operations hold no Store lock. A tag-specific revision prevents an older save from clearing newer dirty state. Failed saves preserve in-memory tags, pins and notes, publish their actual error through source health/notifications, and retry on the next edit, persistence flush after five seconds, or close. Unreadable existing tags are preserved without replacement. Reads and writes are limited to 2 MiB.

The simpler alternative was atomic replacement alone. It fixes torn files but permits older concurrent snapshots to replace newer ones; serialization around snapshot capture is necessary. A database or background service would add unnecessary dependencies and migration effort. The remaining synchronous save latency is paid for a user edit, never while holding the Store lock.

Acceptance evidence in `tests/test_state_reliability.py` covers failed replacement, disk-full diagnostics, latest-state retry, old JSON compatibility, concurrent updates, nonblocking Store access, continuous readers, killing a subprocess after staging, restart, and bounded writes. These tests inspect complete saved values, rather than just mocking a successful helper call. The source tests retain the existing user-visible actions and notification path.

Run:

```bash
.venv/bin/python -m pytest -q tests/test_state_reliability.py
```

The controlled initial comparison used 80 equivalent 1 KiB note publications on this Linux local overlay filesystem. Median publication was 0.013806 ms before and 0.023836 ms after; p95 was 0.056706 ms and 0.056947 ms. These numbers describe this small local fixture, not a power-loss or production filesystem qualification. fsync deliberately adds durability work; no speedup is claimed. The fixture and initial raw results are in `scripts/benchmark_state_reliability.py` and `../measurements/state-*.json`. Final measurement revalidation follows source freeze.

Skeptical review resolved two substantive findings: checking the size before copying a large snapshot, and retaining an unreadable original instead of replacing it with a newly empty tag map. The atomic utility's staging file can remain after SIGKILL; it is not treated as the committed state. Network filesystem mutation is governed by W05.

Upgrade reads existing plain `tags.json` without migration. Rollback can still read new tag files because the format is unchanged. Always close the old writer before switching versions.
