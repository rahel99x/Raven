## Evidence classes

At the final catalog audit there were **67 operation contracts**, **59 worker
operation descriptors**, **56 proposal entries**, **18 deferred paths**, and
**78 published JSON Schemas**. The initial audit had 57 contracts, 44 worker
descriptors and 64 schemas; the source-bound JSON records the current snapshot. These are different sets; none is a completion
percentage. In particular, the 18 deferred paths include bounded file access,
source collection and placement limitations as well as missing action drivers.
Calling them “18 execution drivers” was unsupported. The exact paths and reasons
are retained in the audit rather than silently deleting difficult integrations.

Each operation's `availability`, `apply` and `implemented_worker_adapter` fields
are retained separately. An analysis kernel, a prepared plan, an executable
target handoff, a simulated regression, a real container run and real-site
qualification are distinct claims. No new driver is authorized solely by this
documentation audit. Existing device, multi-node, site, user and research gates
remain in the proposal ledger.

`scripts/audit_capabilities.py --refresh-ledger --output ...` derives current
counts/routes from the runtime catalog, hashes every runtime Python source and
published schema, and regenerates
the published ledger. The simpler alternative, hand-editing counts, would
reintroduce drift. No new runtime dependency, UI, collector or background work
is added. Historical test totals and performance figures remain explicitly tied
to their original records; this audit does not claim a new complete suite run.
