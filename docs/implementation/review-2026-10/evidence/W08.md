## Verified baseline and design

The baseline already has `--ui-trace`, `_timed_ui` phase spans, private exclusive
file creation, bounded summary windows, and file writing after curses exits.
It lacks a Chrome trace-event timeline and background-task correlation.
Reusing that CLI/report avoids a second recorder, new default background I/O,
or a separate configuration path. The simpler alternative—export only aggregate
phase percentiles—cannot reconstruct nested stalls or queue-to-execution delay.

The additive `traceEvents` array preserves `raven.ui-trace/v1` summaries. A
fixed 8,192-event ring holds complete spans and flow events using process-local
monotonic timestamps, process/native-thread IDs, and opaque correlation IDs.
Labels are UI phases or known scheduler lanes; task arguments and callable
names are never recorded. Local worker submissions are wrapped at the existing
WorkerLane seam after caller admission. Original callable metadata is preserved.
Remote execution internals remain outside this process's trace scope.

Producer work is O(1) per event with bounded retained memory. Export sorts the
bounded ring after shutdown. Tracing off adds only an optional-attribute check
to worker submission; the existing direct UI timing bypass remains unchanged.
No paint/input operation writes report bytes. The existing new-file reservation
and error feedback remain in place. Overwrites and unfinished tasks explicitly
make timeline coverage incomplete.

  v57.2**: outer `document` 25.252096 ms, inner `paint` 25.108601 ms. This is a

- An independent correlation check initially found `flow_no_enclosing_slice`
  and zero flows: the finish timestamp preceded its worker slice. The fix adds
  a bounded submission span and emits finish inside the execution/cancellation

## Performance and limits

The existing `scripts/benchmark_ui.py` accepts `--ui-trace` so equivalent
published-data fixtures compare capture off/on without frame file I/O. Three
interleaved fresh processes per condition each rendered 100 synthetic 100-job
frames. The source was frozen at `/tmp/raven-review-w20`; aggregate source-manifest
SHA-256 is `d5036e09fbc8d0450bb3bc34efc6db270448d0bda4370756fd3ba54b80d77fd8`.
This avoids attributing concurrent working-tree edits to the measured revision.

| Source / capture | Frame median ms | Frame p95 ms |
| --- | ---: | ---: |
| Baseline / off | 5.046 | 6.042 |
| Baseline / summary only | 5.268 | 6.172 |
| Candidate / off | 5.353 | 6.522 |
| Candidate / timeline | 5.493 | 6.702 |

These are medians of three per-process quantiles. Candidate timeline capture
adds **0.140 ms/frame**, below the predeclared **0.5 ms/frame** budget; its p95
adds **0.180 ms**. The integrated candidate capture-off median is **6.1% higher**
than baseline, exceeding the nominal 5% regression threshold. The three
candidate medians span 5.032–5.605 ms versus baseline 5.015–5.217 ms, so this small
sample does not isolate variation from an integration regression. Compose and
control publication account for most of the difference; the tracing-off UI
bypass itself is unchanged. This integrated gate remains pending attribution
and final-revision measurement at that stage; the final comparison below
resolves it rather than reporting the preliminary variation as a tracing gain.
Other accepted packages are present in the frozen candidate. These are
counting-painter CPU frames, not terminal transport latency. No measured frame
attempted scheduler/file I/O. See [complete clean samples](W08-frame-measurements.json).

An earlier favorable frame comparison was discarded because another agent's
short test run may have overlapped it. Only the uncontested repeat appears in
the table above. The discarded temporary result was subsequently lost in the
host restart and is not used as acceptance evidence.

The first attempted run stopped on a package-discovery metadata incompatibility;
that failed run is excluded. The shared source loader was corrected for the
new declared namespace layout before the complete comparison above.

The controlled 100,000-call empty-operation fixture used three interleaved fresh
processes per baseline/candidate and off/on condition. Median tracing-off cost
was 0.142 → 0.152 µs/call (about 10 ns additional; this path's implementation is
unchanged). Capture-on cost was 6.091 → 10.305 µs/call: the new timeline costs
4.214 µs more than summary-only tracing. Peak process RSS increased from 9.125
to 14.250 MiB with capture enabled. It did not grow between 50,000 and 100,000
events; the candidate retained exactly 8,192 events. This measures empty phase
calls, not complete frames or user input latency. See
[raw samples](W08-micro-measurements.json) and
[environment/source hashes](W08-W20-source-evidence.json).

The ring deliberately drops old timeline events. It does not replace the
whole-session phase counters. A killed process may leave the reserved output
empty; this opt-in diagnostic is not a durable application journal. Perfetto
parser qualification does not establish GPU, multi-node, SSH or end-user
terminal latency behavior. See [the user guide](../../../guides/self-tracing.md).
