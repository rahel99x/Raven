# W03 — Bounded, attempt-aware accounting

Source: A-02. Baseline: `33316a08bd583a242356c7722a21c10e00cff21b`; final integrated revision is recorded in the parent ledger.

## Verification and implementation

The baseline historical-log query explicitly used `sacct -S 1970-01-01`. It also preferred a current `scontrol` row by bare job number, which could borrow a recycled job's log paths. Further inspection found `fin_steps` and `submit_info` omitted explicit accounting bounds; these related paths were included because `sacct -j` can otherwise search from epoch zero.

Known attempts now use a four-day envelope centered on their retained scheduler submission date, regardless of how old that date is. The default for missing submission time is **14 days**, with missing identity reported as unknown rather than permission to borrow another attempt's paths. `historyrange START END` provides an explicit, persisted range (maximum 3,650 days); `historyrange all` clears that override and does not request unlimited history. Query counts and effective start/end bounds are retained in source diagnostics and shown in Sources.

Queries request duplicates (`-D`) and verify exact job/array/component, owner, submission, start and cluster where retained. `record_details`, `record_submit_info`, and `record_fin_steps` carry selected-record identity through the existing sampler, log export and reviewed resubmission paths. Stale cursor/generation publication remains guarded. Historical-detail caches are bound to retained identity rather than bare job number.

Completed steps require a verified parent attempt and a step start within its start/end interval. Real Slurm evidence showed that a step's `Submit` is its own creation time, so requiring it to equal the parent would wrongly discard valid statistics. This design correction is based on the recorded W14 corpus.

Lost-ack orchestration recovery uses `intent_submit_info(job_id, since)` to bound its query around the retained intent timestamp. The existing exact reviewed command, submission token and working-directory ownership checks remain mandatory; the time envelope alone never authorizes adoption or resubmission. No automatic scientific submission was introduced.

## Alternatives and failure behavior

A simpler fixed 14-day horizon would lose legitimate old attempts. The chosen per-attempt window avoids that loss without scanning all history. Broadening automatically on an empty result would hide scheduler outages and increase load; the implementation instead reports delayed/missing accounting and lets the user request a bounded range explicitly.

Naive remote wall-clock times are not silently compared with timezone-aware instants. Such mismatches remain unverified. W15 supplies consistent UTC-aware structured identities for its qualified readers. Legacy fields containing literal separators are rejected as ambiguous. Unsupported historical stdout/stderr columns are still capability-cached, while transient failures remain retryable.

## Acceptance and qualification

`tests/test_finished_log_backend.py` retains existing path/null/array/delay/cache assertions and adds retained-old dates, missing submission, explicit wider lookup/reset, recycled IDs, owner/cluster/start mismatches, equivalent aware timezones, mixed-zone abstention, and bounded invalid ranges. `tests/test_slurm_json.py` exercises the real recorded controller/accounting format, including requeued duplicates. Root integration tests cover controller and orchestration invocation of the new identity-bearing methods.

The default log-path history changes from an epoch-wide interval to 14 days; known attempts use four days. This is a measured command-shape/window improvement, not a claimed database latency speedup. One lookup still uses one data query; capability discovery can add one cached local `--help` call per command. Historical records are not deleted or rewritten. The real single-node Slurm container qualifies only the exercised command semantics; production cluster retention, remote timezone configuration and filesystem/site policy remain separate gates.

The W30 recovery review also exposed the existing checkpoint restart's bare
`sacct --jobs` lookup. It now requires a known scheduler user and a four-day
window around the retained source start, while preserving exact logical/raw ID,
cluster, start and terminal-state checks. The campaign regression asserts the
literal user/start/end arguments, and changed or active attempts still refuse
restart. This closes an additional accounting entry point rather than relying
on the new general backend API alone.

Real Slurm 23.11.11 qualification exposed another legacy-format distinction:
step rows have an empty `User` while the parent explicitly names its owner.
Only that absent child field inherits the verified parent owner. A unique parent,
user-scoped bounded query, matching cluster and step-start interval remain
required; explicit contradictions and duplicate matching step IDs refuse
attribution. The exact real 16-column rows and adversarial variants are retained
in `test_real_2311_empty_step_owner_inherits_only_unique_verified_parent`.

Final focused integration: **945 tests passed in 29.70 s** across parser/accounting, managed collection, all four planning packages, existing launch/orchestration/worker paths and UI/setup. Exact command and source hashes: `slurm-planning-focused.json`; raw output: `slurm-planning-focused.log`. This complements, rather than replaces, the final integrated full regression.

23.02.8, 23.11.11, 24.05.8, 24.11.7 and 26.05.5**. These runs exercised actual

unavailable rather than fabricated.

qualification remain outside this evidence. Earlier failed runs are preserved
