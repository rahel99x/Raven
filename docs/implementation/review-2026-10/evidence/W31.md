# W31 — Optional allocation health receipts

Source: B-06; baseline `33316a08bd583a242356c7722a21c10e00cff21b`.
This package adds an explicit reviewed operation; it adds no startup probe.
Automatically benchmarking every worker and stopping scientific jobs are excluded
as required by the accepted handoff.

## Implementation and tradeoff

The existing Operations workbench exposes `allocation-health`. Review displays
the authenticated worker identity, chosen memory/scratch/conditional MPI probes, buffer size,
repetitions, warmup and resource limits. Apply dispatches the dedicated
`allocation-health-probe` contract to an owned task process. The worker overwrites
execution identity; caller-supplied context cannot grant probe authority.
Review and Apply must match that same verified execution identity. Receipts are
published to a new private directory using the existing immutable publication
protocol. Cancellation or an uncertain response never triggers automatic retry.

A shell microbenchmark would be shorter to implement, but would add executable
configuration, host-tool dependencies and ambiguous ownership. Two fixed Python
probes keep the first adapter bounded and inspectable. They measure verified
bytearray copies and cached scratch write/fsync/read; they do **not** establish
peak bandwidth, distributed durability, or hardware health ground truth.

Scratch directories must be owned by the user, inaccessible to writes by other
users, free of symlink components, and unchanged since review. The task pins a
directory descriptor and uses an anonymous temporary file; process exit cleans
it, including termination. Peak scratch is 16 MiB, peak buffers are 32 MiB, and
aggregate I/O follows reviewed size and repetition count. The wall budget includes
hardware discovery; the supervised task also enforces CPU/memory/time.
There is no scientific-job cancellation API in this operation.

Receipts retain CPU topology/affinity, model, host, Python/libc/kernel versions,
worker/allocation placement, raw warmup and measurement results, byte verification,
median/range, resource limits and explicit interference/uncertainty. Memory-only
cohorts can compare matching nodes. Scratch comparisons remain host-local because
numeric device IDs do not identify equivalent filesystems across hosts. The
descriptive warning requires matching cohorts, repeated stable observations and
a duration above 1.5 times the supplied baseline. Sparse, incompatible or malformed
baselines abstain; a warning does not diagnose a causal “sick node”.

## Qualification limits

The conditional same-host MPI adapter requires trusted Open MPI 5 development
tools and two authenticated worker CPUs. GPU and inter-node adapters remain
unavailable; local success does not qualify those devices or fabrics. Kernel I/O
stalls can delay termination. Repeated same-host microbenchmarks establish local repeatability only,
not site-wide hardware cohorts or useful causal diagnoses. Production efficacy
requires authorized representative allocations and retained cohort baselines.

## Conditional MPI adapter and review

The smaller alternative, invoking an arbitrary site benchmark or accepting a
user command, would bypass reviewed executable and placement boundaries. The
adapter instead compiles one fixed, bounded standard-C program and starts exactly
two same-host ranks. It reuses the existing diagnostic process supervisor; no
new scheduler submission, remote launcher, RPC broker or framing loop is added.
The worker supplies the CPU/memory grant. Both review and Apply contracts admit
at most two CPUs; a one-CPU worker cannot manufacture a larger grant through
request fields.

The adapter verifies every exchanged byte, records excluded warmups and repeated
raw seconds, and pins compiler/runtime/header/library identities. Compiler
source, object and executable are sealed anonymous files. Open MPI's own session
metadata uses a separate private directory watched by an independently owned
pidfd/pipe cleanup process. Per-file resource limits are hard process limits;
8 MiB total storage and 128 temporary entries are watchdog thresholds that can
overshoot between inspections. Cleanup errors remain errors. Same-UID code,
compiler wrappers and administrator-managed libraries are trusted dependencies;
this adapter is not a compiler sandbox.

Skeptical review found that the old one-CPU contract made the MPI choice
unreachable, nested CPU limits attempted to raise an inherited hard limit, and
an inode could exceed signed 64-bit wire bounds. Those seams now use two-CPU
contract ceilings, inherited-limit clamping in the shared supervisor and cleanup owner, and exact
decimal file-identity strings. Review also required explicit original-path
symlink authority checks, a post-pidfd parent check and actual descendant
termination evidence rather than inferring cleanup from a removed directory.
The final focused health/MPI run passed **39 tests in 5.16 seconds** with
`RAVEN_MPI_QUALIFICATION_PREFIX` pointing to the private development fixture.
[W31-mpi-actual.json](W31-mpi-actual.json) retains the actual governed review →
Apply → immutable receipt, verified 1 MiB exchanges, source hashes and actual
running-rank termination observations. The same suite also passed 4 KiB exchanges.
Both cancellation and owner SIGKILL observed a fixed MPI rank, identified its
process lifetime by PID/start ticks, and verified that all observed lifetimes
terminated and the private runtime directory disappeared. Host-init zombie
reaping is not claimed.

The [stronger failure test initially failed](W31-mpi-startup-race.json): an MPI rank could be orphaned before
its first instruction, adopt init or a subreaper, then create session metadata
after cleanup. The two failed fixture paths remained visible after four seconds;
those exact owned leftovers were removed after verifying no live MPI process
remained. The correction passes the launcher's own PID through a wrapper-overwritten
environment field and verifies it before and after parent-death setup, before
MPI initialization. Directory disappearance alone would have missed this bug.

This cloud maps system binary ownership to overflow UID 65534. That UID is
trusted only for ancestors, never executable/header/library/symlink leaves.
Qualification therefore used private current-user-owned copies of the exact
recorded Open MPI 5.0.7 binaries and development files; original/copy paths,
owners and equal hashes are retained in
[W31-mpi-toolchain.json](W31-mpi-toolchain.json). Ordinary root-owned installations
remain supported. Python, compiler subprocesses and system dynamic libraries
remain trusted infrastructure; this is not a transitive toolchain sandbox.
The actual MPI evidence is same-host local-worker qualification, not Slurm MPI,
inter-node, device or production-site efficacy.


## Final controlled cost, including MPI

The final [20-observation receipt](W31-cost-final.json) was collected in the
exclusive root-granted slot after 18 October 2026 01:24:24.292 UTC, with command

review, compilation and cleanup are included. Medians of three untraced runs:

| Probe | Wall (ms) | Parent CPU (ms) | Reaped-child CPU (ms) | Parent peak RSS (KiB) | Largest reaped-child peak RSS (KiB) | Separate Python allocations (bytes) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Disabled | 0.0005 | 0.0021 | 0 | 11,136 | 0 | 0 |
| Memory | 11.993 | 11.995 | 0 | 15,360 | 0 | 2,905,558 |
| Scratch | 13.700 | 13.702 | 0 | 15,448 | 0 | 2,909,253 |
| Memory and scratch | 13.292 | 13.294 | 0 | 15,448 | 0 | 2,910,638 |
| Same-host MPI | 916.183 | 43.391 | 695.982 | 17,964 | 22,144 | 6,027,274 |

Child peak RSS is a maximum of reaped child observations, **not** simultaneous
process-tree memory and not an amount to add to parent RSS. Python allocation
peaks are separate traced runs. The disabled case measures an empty branch;
this does not measure complete Raven startup. MPI exchanges 8 MiB of verified
payload across both ranks over the four total repetitions, plus unmeasured MPI
control traffic. The parent `/proc` observation included about 45.7 MB read
characters and 8.8 MB write characters for imports, tool review, compilation and
runtime; physical read/write counters and child block-I/O counters were zero on
this cached local fixture. These are not network or storage throughput figures.
No Slurm polling/submission occurred and no scientific job ran in this fixture.

All runtime temporary directories were removed. The process audit found no live
MPI/probe child; old terminated `prterun` zombies from separate owner-death tests
remained under host init, so system-wide zombie reaping is not claimed. The
final observations establish opt-in cost. Earlier cost records remain bound to
their earlier source; no speedup or regression is inferred from those unpaired
measurement windows, and no scientific or node-health efficacy is claimed.
