## Baseline and design

The claim that framing lacks fragmentation coverage was stale. Existing worker,
allocation and terminal tests already enumerate split headers/payloads. A focused
61-test characterization passed before extraction and again after extraction.
Those assertions remain. Generated partitions/coalescing extend the corpus;
replacing it with random examples would lose deterministic boundary coverage.

Hypothesis and pytest-xdist are development-only dependencies. Properties compare
observable ordering, identity, stable digests, retained attempts and cleanup—not
copied codec implementations. Child-process failures use bounded deadlines and
`finally` cleanup. A larger external fault-injection service would add machinery
without improving these local ownership assertions.

A separate verified local finding was that the expression evaluator's AST
allowlist imposed no CPU/allocation budget. Nested filtered comprehensions and
string repetition could consume unbounded work. The smallest complete repair adds
shared step/collection/string/integer budgets and pre-allocation checks, while
preserving `ExprError` feedback through existing callers. A subprocess per normal
expression would incur startup cost and complicate context transfer. Fixed
adversarial cases preserve the discovered counterexamples.

## Implementation and checks

- `tests/test_protocol_properties.py`: arbitrary byte partitions/coalescing,
  incomplete records, queue/depth boundaries, malformed UTF-8/JSON, duplicate keys,
  nonfinite values, canonical digest stability, partial-write accounting, and
  captured baseline wire fixtures. A multi-byte memoryview regression prevents
  element-count accounting from bypassing byte limits.
- `tests/test_protocol_contracts.py`: independent JSON Schema comparisons,
  unsupported majors, explicit descriptive extensions and unknown action fields.
- `tests/test_input_properties.py`: arbitrary SGR mouse byte fragmentation, no
  duplicate pointer events, and no escape-sequence leakage into key input.
- `tests/test_expression_budgets.py`: generated arithmetic/comprehensions and
  fixed excessive repetition, nested loops, native aggregate, replacement,
  formatting, integer growth and nested repr cases.
- `tests/test_attempt_series.py`: state agent's generated delayed callbacks,
  duplicate timestamps and requeue/archive isolation (35 examples).
- `tests/test_slurm_parser_safety.py`: Slurm agent's free-text and whitespace/row
  permutation properties; ambiguous identities remain unknown.
- `tests/test_worker_fault_models.py`: actual local worker retry/ack/disconnect
  state machine plus isolated child truncation, SIGSTOP and SIGKILL cleanup.

## Final profiling handoff

## Setup validation batching (integration discovery)

The full-suite profile identified repeated development setup as the largest
individual test cost and an actual first-install cost. The preserved driver is
`raw/W11-setup-baseline.py.txt`, SHA256
`8d0ce6fcea20eb4bc8e7e642a3f3c8d0468aa201eeb5bc430cd4c4d349bf7ed3`.
It launches a fresh interpreter for each of 48 ASCII/Unicode frames.

The revised driver starts one child with the selected virtual environment's
interpreter. Within that child, each case invokes the real
`raven.raven_launch.light_main`: configuration resolution, policy admission,
new Session/App/Store, fake scheduler parsing, settling, rendering and ordinary
`Session.close` are retained. Only interpreter/module imports are shared.
The parent checks the exact ordered case manifest, including successful exit
and text validation for every case. JSON source-launcher, report and doctor
checks remain separate real subprocesses. No live scheduler call is introduced;
setup remains offline by default and preserves existing personal files.

Calling the renderer directly would be shorter but would skip the launcher,
configuration and lifecycle boundaries. Running all cases in the setup parent
would use the wrong interpreter before installation. A selected-interpreter
child preserves those boundaries without 48 cold imports. Existing ASCII and
Unicode assertions remain; ASCII now also explicitly rejects escape sequences.
Errors name the exact failed case before any report is published.

Independent source review found no substantive defect. The focused command
`.venv/bin/python -m pytest -q tests/test_setup.py --basetemp=/tmp/rv-setup --durations=8`
passed 16 tests in 102.90s during concurrent functional work; this is not a
controlled timing comparison. The new lifecycle regression executes 49 full
launches, verifies distinct App/Store identities and normal shutdown before the
next case, no surviving worker threads or file-descriptor growth, restored
process router/clock/streams/environment/signals/arguments/search path, and the
same deterministic frame before and after all other cases. Existing repeatable
setup, personal plugin/config/state protection, pip-free environment, no-clobber
report, selected profile and no-Slurm-execution assertions pass unchanged.

`scripts/benchmark_setup.py` compares the exact preserved and revised drivers
against one frozen current Raven source. It alternates order, uses fresh pip-free
venvs and identical 48-case fixtures, records full commands and direct setup

process RSS, individual RSS and wall time. It uses no tracemalloc. Its tiny
