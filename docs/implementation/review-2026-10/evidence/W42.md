## Audit and extraction milestone

W22's conservative import graph reaches 224 of the baseline 269 modules from
launch/controller; lazy imports are included. Renaming those modules into seven
folders would not create a small independently auditable core. The chosen first
extraction instead builds **unpublished** core and lab distributions with disjoint
file ownership. An extra alone was rejected because it changes dependencies,
not installed Raven source. Ordinary production packaging and all three entry
points remain unchanged until the W44 workflow gate and further decomposition
establish that a production split helps users and administrators.

The prototype captures one source snapshot for a full comparison wheel, a core
wheel and a matching lab wheel. It removes 16 scientific/analysis modules from
core, retains telemetry modules used by normal monitoring, ships the new typed
transport helper, and includes an explicit profile manifest. Only profile-declared
missing extensions may be absent; unrelated import failures remain errors. Core
shows actionable missing-extension feedback and hides unavailable contextual
controls while retaining saved tool favorites. Worker build identity includes
the distribution profile, preventing mixed-profile reuse.

## Actual installation and compatibility qualification

`python scripts/distribution_prototype.py --output /workspace/raven-distribution-final-3`
passed. Clean private virtual environments exercised an 80-column synthetic
monitor, actual local job launch, retained logs, exact Run home, trusted plugin
API, an actual installed Heavy child, and all three installed entry points with
optional terminal dependencies absent. Lab restoration/removal/reinstallation,
real package upgrade to `7.0.0+qualification1`, downgrade to `7.0.0`, and refusal
of a mismatched lab dependency all passed. The extra local version is a packaging
fixture over identical application bytes, not a claim about future migrations.
User config/recording hashes and saved optional-tool pins remained unchanged.
Wheel and sdist Raven contents matched exactly and core/lab files do not overlap.

The first installed core render exposed a real missing-extension `KeyError` in
contextual controls. The fix skips only explicitly declared absent extensions;
production missing builtins are still errors. Review also found that filtering
saved favorites through only installed tools would erase optional favorites;
their identities now survive extension removal. Behavioral assertions were kept.

## Measurements and limits

The final complete/core/lab packages contain **326 / 310 / 16** Python modules.
The controlled comparison created two clean installations from the same final
source snapshot, used two warmup pairs, then alternated full/core order over eight
fresh-process pairs. Two further pairs measured Python allocations separately.
All 24 observations executed the existing probe's common `complete` path with
identical logical jobs, resources, completed local run, retained log, managed-worker
search result, config bytes and synthetic scheduler commands. Installed files
matched their wheels, and runtime hashes remained unchanged through the window.

The exclusive measurement window was **2026-10-18 01:59:14.579–01:59:40.100 UTC**.
[W42-controlled.json](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/W42-controlled.json) contains the method, artifacts, ranges
and paired differences. The [raw report and reproducible harness](https://github.com/rahel99x/Raven/tree/b98742fb967f18131905696f4afd3a61f2ad03f2/docs/implementation/review-2026-10/measurements/distribution-final/)
retain every observation, command, imported module list and unnormalized frame.
The original workflow and instrumented AST output are included for review.

The core removes **3.6%** of shipped bytes and **3.5%** of installed logical bytes
in these environments; installation footprint excludes Python, pip and the
standard library. First-frame differences favored core in all eight pairs, by
**3.17–30.38 ms**. Whole-process differences ranged from **51.61 ms faster to
18.81 ms slower**; workflow and parent CPU also had individual regressions.
The small import-phase difference overlaps ordinary run variation. Parent
character reads/writes fell from median **24,838,246 / 1,895,475** to
**23,712,272 / 1,819,585**; physical block counters were zero under the warm cache.
These counters exclude child I/O and do not establish storage-throughput gains.

This is an instrumented 80-column **probe render**, not installed-CLI interactive
readiness or human launch time. The fixed synthetic queue performs no real Slurm
requests; local launch and worker execution are real. First-import module counts
are unchanged at 53; the reduction appears when the workflow builds the operation
catalog. Raw frames differ in the wall clock and the intentionally absent optional
lab repair action; full display equality is not claimed. Filesystem/page caches
were warm, and the sample is too small for population-level speed guarantees.
Parent and reaped-child CPU are reported separately, not as sampled aggregate
process-tree CPU. Child RSS maxima may inherit fork high-water marks and are not
summed with parent RSS; Python allocations are a separate quantity.

An independent read-only review found no blocking comparison or statistics issue
and required these interpretation limits. Every command exited successfully.
The [post-window process audit](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/measurements/distribution-final/child-audit.json)
found no live process using either qualification's private interpreter/artifact
roots and no unreadable process entries. This is normal-success cleanup evidence;
on a timeout or abnormal exit, abort the run and audit/clean only owned descendants
before another sample. The retained results do not qualify that failure path.

Reproduce with the archived harness after the functional extraction succeeds,
using a new output directory and an otherwise quiet host:
