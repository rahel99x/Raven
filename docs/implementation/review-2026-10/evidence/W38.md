# W38 — Optional per-user session service

Source A-09; baseline `33316a08bd583a242356c7722a21c10e00cff21b` contains a durable
read-only supervisor and shared-query cache, but no Store/Sampler-owning Unix
session protocol or reconnecting client. The supervisor's lock/ownership lessons,
existing managed builder, Store, Sampler, collection ledger/cache, shared framing
and W18 UI wake primitive are reused.

## Delivered milestone and boundary

The explicit optional module command owns one managed Light session in a private
local directory. A kernel writer lock is acquired before constructing collection.
Linux peer credentials and socket0600/directory0700 restrict access to this user.
The `raven.session/v1` contract exposes read-only hello/snapshot/events, exact
session identity, process epoch, sequence cursor, source timestamps and replay
gaps. Clients cannot request collection, reset scheduler deadlines, submit actions,
read files or claim an allocation. Existing Light site admission remains active.

Delivered clients are one-shot JSON, reconnecting watch, a compact scrollable
terminal, and an installed-only SSH bridge. Notebook/editor/portal examples use
the same contract. The terminal's one background reader publishes one latest
result through W18's coalesced wakeup; IPC cannot block keyboard input. Normal
launchers remain available and never start the daemon automatically.

This is the explicit **read-only observation milestone**. It is not a claim that
the full ordinary curses workspace or verified Heavy worker has migrated into a
daemon. Heavy ownership/action integration remains outside this milestone; no
adoption, cancellation or replay occurs on service restart. Existing remote
source-shipping is retained for operations without this installed contract. Its
replacement requires corresponding operation parity and profiling, rather than
assuming a compact job projection can substitute for arbitrary evidence reads.

The simpler alternative of polling the existing supervisor's JSON file avoids a
socket but lacks live peer authentication, negotiated versions and bounded replay
semantics. Rebuilding a second sampler would duplicate site budgets. Reusing the
managed builder costs more initialization than a new minimal queue reader but
preserves its actual scheduler admission and source-health semantics.

## Recovery, limits and review

Restart retains the same session identity and previous observation, initially
stale, but changes epoch and explicitly reports replay loss. Only an acquired
kernel lock permits stale socket cleanup, and unrelated files/unsafe paths are
refused. A failed read never advances the client cursor. A failed publication
retains its prior exact identity and snapshot. Authoritative persisted fields and
client envelopes validate before use, including identity, time, row type, replay
order and action semantics.

Requests: 16 KiB; response: 2 MiB; retained replay: 64 descriptors; maximum clients:
64; aggregate pending output: 8 MiB; read quota: 32/s with burst64. Slow peers are
dropped independently. Lists report explicit omitted counts; their projection
excludes commands, work directories, logs/config and large telemetry histories.
An oversized publication marks retained state stale and surfaces the read error.
Publication age and actual queue observation age are shown separately; successful
unrelated source polling cannot hide a queue error.

Independent review found incomplete retained/response validation, ambiguous age
labels and blocking network reads on the UI thread. All three are corrected and
covered. A narrow extension point lets W39 supply an independently trusted shared
service UID and authorization policy without weakening same-user defaults.

## Validation and qualification

Latest combined session/shared/WASI tests: **80 passed in 4.67s**. Session
cases cover actual Unix sockets, multiple clients without new collection, writer
exclusion, restart continuity, stale sockets, unrelated-path refusal, scope
mismatch, replay expiration, protocol/action rejection, shared-codec fragmentation,
peer refusal, retained cursor, aggregate queue/rate budgets, malformed retained
state, invalid responses, and nonblocking UI reader shutdown. Actual subprocess
demo startup/restart and cleanup are tested.

[Installed loopback qualification](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W38-installed-ssh.json): a built wheel is
installed into a clean venv; the SSH bridge executes that site's installed module,
not the checkout. The owned daemon is killed without cleanup, a remote read fails
without losing its cursor, restart preserves the session with a new epoch/gap,
protocol999 is rejected, and normal shutdown removes the owned socket. Generated
SSH keys and processes are cleaned up. Strict client host-key checking remains
enabled. Only the isolated test server uses StrictModes=no because this sandbox
remaps root-owned paths. Scheduler observations are explicitly simulated.

The no-isolation build first exposed missing declared build prerequisites in the
execution venv; installing setuptools84.0.0 and wheel0.48.0 resolved the environment
issue. The actual installed bridge then passed. This is not production cluster,
live Slurm, administrator lifecycle or Heavy service qualification.

Controlled W39 fixtures measure the reused protocol/response core with 1/10/200
logical clients, exact row fidelity and actual bounded socket bursts. The later
full Store/Sampler lifecycle measurement below closes the separate local resource
qualification requirement; no source-shipping improvement is claimed. Final
integrated checks and revision binding remain tranche gates. The [guide](../../../guides/session-service.md) documents
installation, client commands, protocol bounds, recovery and rollback.

## Final IPC maintenance review

Read-only review of `bab48f6` found two transport correctness gaps: an expired
client deadline was clamped to a positive timeout, allowing slow partial bytes
to extend an exchange, and a ninth complete coalesced request could remain in
the decoder until another network byte arrived. Four controlled/coalesced
regressions reproduced these failures before changing production code. The
[baseline report](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W38-IPC-baseline-reproduction.txt) is retained.

Revision `0d138fd` applies one absolute deadline across connect, send, receive
and final response acceptance; failure preserves the client's identity/cursor.
The selector owner drains one bounded batch of complete buffered frames per
peer before waiting. Partial frames do not trigger busy polling, and existing
authentication, admission quotas, output bounds and write budgets remain intact.
An independent protocol maintainer approved the production diff. Their test
review made admission time deterministic only for the coalesced-request fixture
and replaced a weak fixture-only assertion with the actual unchanged publication
sequence. The real slow-drip, late-response, 9/17-frame and existing session/shared
suites passed **82 tests in 3.49 seconds**. Exact commands, source hashes and
qualification limits are in the [focused receipt](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W38-IPC-regression.json).

## Full daemon lifecycle and resource measurement

The [reproducible lifecycle harness](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W38-W39-lifecycle-harness.py) ran on
`0d138fd` in an exclusive window, 02:01:07–02:04:19 UTC on 18 October 2026.
It uses the actual managed Store/Sampler with fixed simulated scheduler data,
first directly and then through the actual session daemon. Both primary phases
retain observations for 60 seconds; the daemon receives 598 successful read
exchanges, each reconnecting a real Unix socket. Exact complete jobs/finished-row
hashes match across both phases. Publication/health clocks remain real and are
not claimed byte-identical. The requested Ultra preference remains inactive in
Light: the existing Light cadence/admission policy still applies.

After a separately recorded 3.8-second warmup, the steady windows measured:

| Case | Steady time (s) | Process CPU (s) | RSS first / last (KiB) | Descriptors | Threads |
| --- | ---: | ---: | ---: | ---: | ---: |
| Direct current Store/Sampler | 56.15 | 0.05 | 34,936 / 34,944 | 3 / 3 | 3 / 3 |
| Actual daemon and reconnecting clients | 56.19 | 0.31 | 35,164 / 35,284 | 6 / 6 | 3 / 3 |

Cold availability was 2.181/2.269 seconds respectively. Daemon reads averaged
1.94 ms and reached 80.54 ms in this run; none failed. The simulator recorded
three/two `squeue` calls and one `sacct` call per phase. A collection deadline
near the 60-second boundary can land on either side of the stop, so these are
not equal-command-count scheduler-load measurements or a causal efficiency
claim. Client queries did not request collection. The driver and client CPU are
outside the service-process CPU column. Physical `read_bytes`/`write_bytes`
counters were zero; that does not imply zero cached file or socket traffic.
The raw report retains character I/O, warmup samples and process maxima separately.

After normal shutdown, a failed read preserved the cursor. A six-second restart
phase served 59 additional exchanges, retained the same session, generated a new
epoch and explicit replay gap, and made retained context available in 0.186 seconds.
That is retained availability, not a new scheduler observation. Owned processes
were joined and socket paths removed after every phase. No descendant process
was observed during measured intervals. RSS is OS process memory, not Python
allocation or a process-tree peak; this short plateau does not prove freedom
from long-term leaks. [Raw measurements](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W38-W39-lifecycle.json) include
the exact source/harness hashes. The first fixture attempt stopped before
measurement because this host omits `/proc/PID/task/PID/children`; the harness
uses `/proc/*/stat` parent identities instead. That [fixture correction](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W38-W39-lifecycle-attempt1.json)
is preserved and did not change Raven.

The inherited dispatch change was then requalified with the final-3 installed
wheel, without rebuilding it: actual loopback SSH, crash/restart, cursor retention,
new epoch/gap, version rejection and owned socket cleanup all passed. The
[functional receipt](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W38-installed-ssh-ipc-final-run.json) records the exact
command, wheel SHA256, `0d138fd` source hashes and separate 02:05:28–02:05:33 UTC
window; [results](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/raw/W38-installed-ssh-ipc-final.json) retain the simulated-source
and isolated server StrictModes limits. These checks do not qualify a remote
production cluster.

Final installation review also exposed a platform compatibility limit: ordinary
persistent-state ownership currently requires qualified Linux/WSL2 local storage;
macOS persistent state is unsupported, with stateless use separately documented.
No macOS execution is claimed. This ordinary-state limitation is distinct from
the optional session service's explicit Linux `SO_PEERCRED` requirement.
