# W18 — Wakeable UI and deadline-driven waits

Source: Review A items 4 and 11, with the handoff's correction that existing
selector brokers and fragmentation tests are retained. Baseline revision:
`33316a08bd583a242356c7722a21c10e00cff21b`. Final integrated revision and source
hashes are recorded by the coverage ledger.

## Verified baseline and design

The existing UI already preserves bounded input batches, a differential painter,
quiet managed Jobs documents, and independent animation/maintenance deadlines.
It waits through curses with a maximum 200 ms timeout, forces a 16 ms timeout
for an embedded terminal, and forces 5 ms while a fragmented control sequence
is pending. The baseline's actual 45-second, 100-job simulated idle PTY measured
2.067% of one CPU; the review's historical 5–6% is not the current baseline.

The simplest alternative is shortening all timeouts. That improves some
publication delays while increasing idle wakeups and retaining fragment spins.
The adopted change instead waits on stdin, one coalesced nonblocking socketpair,
and readiness hints from the existing terminal/allocation clients. The UI never
reads those clients' sockets. Their existing finite `poll`/`tick` methods keep
protocol, lifecycle, and ownership decisions.

Store publications, archive merges, governed worker completion, and allocation
verification/recovery completion notify a typed wakeup primitive. No arbitrary
callback runs while holding Store's lock. Producers write at most one byte per
pending burst; shutdown detaches the wakeup and later completions become no-ops.
Two socket descriptors and one selector descriptor are the bounded resource cost.

## Complete runtime path

Curses-buffered input is drained before every selector sleep. A lone Escape uses
its actual ambiguity deadline; incomplete UTF-8, paste, CSI, SS3, and pointer
frames await additional bytes without a 5 ms timer. Existing framing, pointer
ownership, and input budgets are preserved. Complete buffered transport frames
wake immediately, including invalid headers so the owning decoder can reject
them. EOF/hangup is observed without consuming input bytes.

The UI retains the 200 ms maintenance deadline because existing feature providers
do not all advertise individual deadlines. Quiet unchanged Jobs maintenance can
skip feedback and paint, while visible progress icons have explicit 400/800 ms
boundaries. Real input, terminal publications, geometry, and existing animation
deadlines still request their frames. Unsupported/nonpollable stdin or descriptor
exhaustion uses the prior bounded curses timeout, including the terminal fallback.
No new user setting or daemon is required.

WorkerClient bounded result/close waits now use its existing selector. The
allocation helper mirrors readiness interests without taking pipe ownership,
derives waits from queue, pending, lease, idle-release and summary deadlines,
and preserves bounded cancellation checks. The terminal broker's own polling
and short final child-reaping loops remain unchanged; this is an incremental
conversion, not a claim that every timer in Raven has disappeared.

## Validation and review

- Existing pointer/input burst, fragmentation, quiet-frame, worker/allocation,
  protocol-fault and actual outer-PTY tests are reused.
- New checks exercise 100,000 coalesced notifications, concurrent publication
  and drain, closed producers, fd exhaustion, complete buffered frames,
  unconsumed owner bytes, EOF, failure completion, trusted publication hooks,
  Escape deadlines and exact icon deadlines.
- A review caught hover feedback being suppressible on the same turn as quiet
  maintenance. An explicit pending-input paint flag preserves that behavior.

  second read changed an embedding window's hover/frame sequence. Nonpollable
  terminals now retain the original single blocking-read path (which itself
  returns buffered input immediately). Existing frame-count, timeout, selection,
  mark and paint-before-click assertions remain unchanged.
- Focused existing input/frame/progress/PTY/synchronized-output selection:
  **305 passed** after the deadline, fallback, and harness corrections.
  Worker/allocation/protocol selection: **190 existing tests passed**; trace/worker compatibility selection **116 passed**; final
  integrated totals will supersede these iteration results.
- Shared framing architecture, formatting and strict typing gates passed after
  the readiness property was added. No second framing/parser implementation
  was introduced.

## Measurement status

The following historical attempts are retained for audit. The final clean
comparison below supersedes their pending gate. The existing
`benchmark_raven_resources.py` now optionally measures an actual embedded
`/bin/sh` PTY, counts UI waits, and probes input-write-to-dispatch and synthetic
Store-publication-to-curses-flush latency. It checks exact input order/count and
records namespace module hashes. These probes are not scheduler response time,
terminal pixel latency or live cluster qualification. Idle CPU measurements run
without latency injection; publication/input runs are separate fixtures.

The sub-1% idle target is a target on the documented local fixture, not a claim
about every terminal, workload, or embedded shell. The final measurement misses
that target; gains and regressions are recorded below.

The first frozen integration's uncontested measurements are retained in
[W18-first-measurements.json](https://github.com/rahel99x/Raven/blob/evidence/pre-review-2026-10-20/docs/implementation/review-2026-10/evidence/W18-first-measurements.json). With one actual idle
embedded shell, CPU changed from 17.31% to 6.47% and UI waits from 53.64/s to
7.62/s over 45-second windows after 5-second warmup. Separate 10-second probes
retained all 47 injected keys and 31 source publications per case. Publication
to flush p95 changed from 183.63 to 11.46 ms without a shell and from 203.77 to
14.49 ms with a shell. Input dispatch p95 changed from 1.81 to 0.35 ms and from
5.75 to 0.45 ms respectively. The no-shell probe CPU increased from 9.40% to
15.20%: earlier, more frequent publications caused additional frames. That cost
is disclosed rather than hidden behind the freshness improvement.

The first no-shell idle pair overlapped another agent's tests/provisioning and
is explicitly discarded. A later review corrected unnecessary paint on early
timeout returns and aligned quiet maintenance with icon boundaries. Those edits
pass the full focused checks but require a fresh controlled comparison; the
first integration's numbers are not asserted for the corrected revision.

### Final clean integrated measurement

All participating agents acknowledged the quiet barrier. The frozen baseline
and integrated source ran from **2026-10-18 00:38:32.706 to 00:42:47.081 UTC**
without reported competing tests/builds/services. The manifest is
`7bc56e0f4145e93d1325fc0bf66afe362d3e93cfd129b3c1e18c0658a9e2cf4b`;
path-qualified hashes are in
`W08-W18-W27-W29-W36-W43-final-source-manifests.json`.
The existing 100-job/25-history, 160×48 outer-PTY fixture uses CPython 3.12.14,
Linux 6.18.55, five visible logical CPUs and a four-core cgroup quota. Idle cases
measure 45 seconds after five seconds of warmup. The embedded `/bin/sh` is real;
scheduler responses and source publications are fixtures.

| Idle case | CPU % of one core before → after | UI waits/s before → after | Process peak RSS bytes before → after |
| --- | ---: | ---: | ---: |
| No embedded shell | 2.022 → 2.200 | 5.022 → 7.289 | 40,374,272 → 43,204,608 |
| Actual embedded shell | 16.644 → 6.222 | 54.198 → 7.644 | 43,880,448 → 46,567,424 |

The no-shell case regresses by **0.178 percentage point of one CPU**; the embedded
shell saves **10.422 percentage points** (62.6% relative). The sub-1% target is
**not met**. The additional publication/deadline wakeups and bounded selector
plumbing have a cost; the integration also contains other accepted packages, so
its RSS increase is not attributed exclusively to this change.

Separate ten-second probes after one second of warmup retained all **47 keys and
31 publications** in each case:

| Probe case | Input dispatch p95 ms before → after | Publication-to-flush p95 ms before → after | CPU % before → after |
| --- | ---: | ---: | ---: |
| No embedded shell | 1.732 → 0.849 | 176.583 → 10.176 | 10.398 → 14.998 |
| Actual embedded shell | 3.487 → 0.300 | 206.384 → 13.649 | 16.498 → 11.297 |

The no-shell probe's **4.599 percentage-point CPU increase** is a real cost of
the lower-latency integrated publication path, not hidden by the latency gain.
The shell probe saves 5.200 points. These are dispatch/completed-curses-flush
latencies, not display pixels, live Slurm or network latency. Every case issued
the same 2 `squeue`, 1 `sacct` and 1 `scontrol` fixture commands. No physical block
read/write bytes were observed; `/proc` logical character counts and full
samples remain in the eight `W18-final-*.json` reports and their combined
`W18-final-measurements.json`. No correctness/fidelity assertion was weakened to
obtain these results. The later opt-in W43 multistyle fallback does not enter
this default-off fixture; the final owned integration selection passed 203 tests.


After measurement, root added a `Store._notify_ui` early return when no UI wake
object is attached. This prevents a headless SSH helper from importing/shipping
UI wake machinery and preserves the existing SSH command-size bound. Attached
UI notifications retain their exact typed contract. The measured snapshot
predates that one guard; final source hashes and root's integration checks bind
the delivered variant. No new numeric claim is inferred from that correction.


The broad discovery suite subsequently found a legacy startup/failure case:
`run_curses(None, ..., store=None)` must still reach wrapper failure and disable
all mouse/paste modes. New attachment code dereferenced the absent owner first.
Four optional-owner guards restore that path without changing normal UI waits.
The existing test and all exact teardown-byte assertions remain unchanged;
smooth-scrolling/raster/wakeup/quiet-frame/sync selection passed **160 tests in
0.85 s**. The final source evidence records this post-measurement startup fix.
