## Baseline, design, and compatibility

The baseline serializes each envelope twice: once for its digest and once to
write the checksummed record. PythonCapture also reconstructs identical code
metadata for every event. These are confirmed code paths; the review's claimed
universal 10–100× overhead is not accepted as a general measurement.

Before changing these paths, `scripts/benchmark_trace.py` ran 27 fresh-process
samples: call-heavy, async/generator, and multithreaded work, each disabled,
legacy-profile, and CPython-monitoring, with three repeats. Local temporary
files use identical 256-event fsync checkpoints and clean finalization. Baseline
monitoring medians were 10.849 ms/409 events (calls), 113.261 ms/3,895 events
(async/generator), and 61.786 ms/1,953 events (threads). Disabled fixtures take
0.018/0.566/0.810 ms respectively; these deliberately tiny functions exaggerate
relative instrumentation slowdown and do not predict a scientific workload.
Peak **process RSS**, process CPU, event count, dropped count, journal bytes,
and application result are retained per sample. No tracemalloc result is
presented as RSS.

The smallest compatible fix serializes the unsigned canonical v1 envelope
once, hashes it, and inserts the checksum at its exact sorted-key position.
Byte-for-byte tests compare the entire encoded record and digest against the
old algorithm, including nested and adversarial string content. All existing
v1 readers, commit cutoffs, crash-prefix checks, and journals remain unchanged.
A bounded 1,024-entry weak-code cache avoids retaining dynamically compiled
code. Immutable metadata is reused; cache eviction cannot change captured data.

CPython monitoring returns DISABLE only for permanently excluded recorder/
protocol code and PY_START/PY_RESUME/PY_RETURN/PY_YIELD local events. It never
uses DISABLE for transient thread/recursion exclusions or unsupported
PY_THROW/PY_UNWIND events. Legacy profiling keeps its explicit coverage limits.

The simpler alternative is leaving per-event work untouched; it preserves
compatibility but retains demonstrably duplicate serialization. A block-format
alternative is measured separately as an experimental encoding lower bound.
It requires a versioned reader, commit-aligned block handling, and migration;
no block-integrity journal is silently substituted for v1.

## User-to-backend export path

`raven trace export MANIFEST --format perfetto|speedscope --output NEWFILE`
reads a verified bounded prefix through the existing TraceReader, converts it,
and exclusively publishes a fully written private file. Invalid journals are
rejected. Read budgets match inspection: managed 512 events/256 KiB;
unmanaged 20,000 events/8 MiB. Existing destinations and symlinks survive;
injected disk failure leaves no partial destination. The raw journal is never
modified and remains the recovery source.

Perfetto shows matched Python/cooperative wall-time spans and observed event
instants. Speedscope supports Python **evented** profiles, never fabricated
sampled CPU stacks. Unmatched prefixes/tails are counted and omitted from frame
intervals rather than closed synthetically. Exact attempt/process identity,
coverage, source/read/commit status, and digest remain in export provenance.
Application metadata and paths are scientific evidence and are not silently
redacted. Native/cooperative-only recordings use Perfetto.

  shared application code across threads, balanced evented profiles, unknown
  prefixes/tails, open committed prefixes, invalid journals, unsupported stack
  semantics, export admission/budgets, exclusive output and storage failures.
- Existing exception, generator/async, fork, ordering, drop-budget, checksum,
  commit/crash-prefix and recorder-lifecycle tests remain unchanged.
- Real CPython **3.10.22** and **3.11.17** each ran the then-current trace/UI/
  export suites: **67 passed, 2 skipped**, with the monitoring-only tests skipped
  appropriately. CPython **3.12** ran the final package selection: **70 passed**.
  The root integrated matrix supplies final-revision totals.
- Independent Perfetto v57.2 parsed exported Python intervals. The official
  speedscope JSON Schema accepted the generated evented profile. Structural
  stack tests additionally check ordering and balanced opens/closes.
- Review found that generic descriptive event data can contain a non-string
  `span_id`, function or line. Export now handles that without treating it as
  executable/security metadata or crashing on an unhashable key. Source
  sequence numbers cannot be overridden by an event's descriptive `seq` field.
- Review replaced direct output creation with exclusive atomic publication,
  so a failed write cannot leave a misleading partial result or delete a
  concurrently replaced destination.

## Controlled measurements and format decision

Three interleaved repetitions per case, CPython 3.12, Linux, local `/tmp`
**tmpfs**. Fsync is exercised but this is not physical-disk durability latency.
Values below are fresh-process medians; RSS is the process high-water mark.

| Fixture / adapter | Baseline wall ms | Candidate wall ms | Change | Process RSS delta MiB |
| --- | ---: | ---: | ---: | ---: |
| Calls / legacy | 11.062 | 9.506 | −14.06% | 0 |
| Calls / monitoring | 9.434 | 8.750 | −7.25% | +0.125 |
| Async-generator / legacy | 131.879 | 119.779 | −9.17% | +0.125 |
| Async-generator / monitoring | 113.425 | 99.495 | −12.28% | +0.125 |
| Threads / legacy | 73.912 | 66.214 | −10.42% | −0.250 |
| Threads / monitoring | 67.666 | 53.121 | −21.50% | −0.125 |

Median event counts and bytes/event matched for every paired case; there were
no dropped events. Thread-library scheduling can vary incidental callbacks
between individual repetitions. Application answers match. The disabled
fixtures vary from −2.75% to +14.54% (−18 to +74 µs absolute); these tiny runs
do not establish a disabled-path gain or a meaningful regression. CPU seconds,
all samples and process RSS are in [the raw comparison](W20-recorder-comparison.json),
with [the pre-edit baseline](W20-recorder-before.json) retained separately.

The identical-payload encoding experiment processes 10,000 events, five
interleaved repeats: v1 double serialization 82.513 ms; v1 single serialization
49.460 ms, both **381.778 bytes/event**. A proposed 64-event v2 block format
costs 12.415 ms and 154.859 bytes/event in this encoding-only lower bound. This
shows a promising storage/encoding direction, not a qualified recorder: it has
no production reader, migration or crash-recovery proof. The adopted fix keeps
exact v1 bytes and achieves the measured end-to-end gains without changing
commit semantics. A block-format migration remains unqualified for deployment
until a complete versioned reader, old/new qualification and physical-storage
experiment demonstrate the additional benefit. No unsupported v2 file is
written by Raven. See [the experiment](W20-integrity-experiment.json) and
[source/environment evidence](W08-W20-source-evidence.json).

The benchmark is a local process/filesystem experiment, not live Slurm, GPU,
remote storage, or MPI qualification. Existing installations need
only the ordinary package update; there is no journal migration. Rollback keeps
v1 recordings readable. See [the user guide](../../../guides/self-tracing.md).
